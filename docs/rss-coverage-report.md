## 3. 実装した機能

既存の監視CLIに `--runs` を追加。明示された親ディレクトリ内の32文字16進実行IDを
対象として、3桁番号JSONのID・SHA-256と取込済み記録を照合する。
未取り込み、内容変更、元ファイルのない取込済み記録を別件数で報告する。
summary.jsonの存在・形式、0始まりの連番、samples・excel_reads・attention_samplesと
各ファイルの記録が一致することを検査する。注意を含む完了実行は注意と報告する。

`complete_runs` はファイル構成と集計の一致数であり、取込完了数ではない。
取込漏れ・変更は別に検査する。summaryの値変更回数や単調時計の履歴は再計算しない。
保存ストア側のRaw再検査は既存監視が担当する。今回のcoverageは取得内容の真偽や
RSS接続・鮮度を証明せず、過去時点の市場データを復元しない。
監視結果のみ標準出力に返し、再取得・再保存・修復・削除・発注は行わない。

## 9. 既知のリスク・制限

観測・取込の書込処理を終了してから検査する。DBと元ファイルの原子的スナップショットはないため、
同時変更中は一貫した判定を保証しない。ストア監視とcoverageのDB読取も別時点である。
対象は最大1,000実行、合計10,000観測、1実行60観測、各JSON1MiB。
それ以外のファイル名は検査対象外。外部へ解決される対象パスは拒否する。
元のファイルを別の場所へ移した場合にも欠落として報告するため、欠落原因は断定しない。
summaryは署名されておらず、集計が一致しても元の実行の真正性は証明できない。
