# フューチャーテストの自動レポート

2026年11月30日寄付から、稼働中のA・B（V21）の記録で日次・週次・年次PDFとSVGチャートを作る。Aの基準日は11月19日、新Bは11月27日。A9・A10は11月27日引けで評価を終了した。停止口座の台帳はローカルのアーカイブで参照できる。

## 保存先と内容

ローカルの C:\Users\i4jll\Desktop\個別株自動売買ツールv1フューチャーテスト に保存する。レポート一覧.html から3種類を開ける。日次/週次/年次の各フォルダーに日付入りPDF、チャートにSVG、変更前のレポートに訂正前の版を残す。OneDriveへの出力は拒否する。

確定資金は初期資金＋売却済み取引の費用控除後純損益。保有株の取得費用は売却時に純損益へ算入し、確定資金から二重控除しない。現在の現金余力・時価純資産とは異なる。保有表には銘柄名、株数、取得日・単価、現在値と価格日、買付費用を含む評価損益と率を載せる。未発生の売却費用は含めない。

期間内・開始来の収益率、同期間TOPIX価格指数比と差（ポイント）、年率Sharpe（無リスク金利0、252営業日、日次標本標準偏差）、PF、最大DD、決済数、支払費用を載せる。Sharpeは観測不足・変動ゼロ、PFは損失決済なしの場合に未算定。含み損を除いた確定損益ベースのDDであり、口座全体の時価リスクとは違う。短期間の値を戦略の優劣の証明に使わない。

日次は当日、週次は月曜から当日、年次は年初から当日。ただし各口座の開始前の実績は作らない。開始前・期間途中を明記する。最終営業日は次の営業日が週/年の外に出ることで確定する。各チャートは開始来で、同じ開始日と初期金額に換算したTOPIXを併記する。

翌営業日表は保存済み確定判断から作る。候補は寄付値・ギャップ・余力などの条件付きであり、注文や約定の保証ではない。既保有は追加買付見送り、停止は取消相当として明記する。翌日判断未取得でも確認済み実績は表示し、未確認を候補ゼロ・保有なしに変換しない。

## 自動実行

- Windowsタスク JPX-ForwardReports-AfterClose: 平日22:50 JST。ユーザーログオン中はCodexアプリを閉じていても実行する。
- 起動補完: Windowsログオン5分後とStartWhenAvailable。失敗時15分間隔で2回再試行。PCの電源断中には実行されず、未取得の市場データを生成しない。
- Codex予約「フューチャーテスト日次・週次・年次レポート」: 平日23:00。既存生成物を検証し、必要な場合だけ再生成する。
- data/forward-reports/config.json に出力先、PDF用Python、Codex予約ID/設定ファイルを保存する。Codex予約がACTIVEでない、削除された、またはautomatic_enabled=falseならWindows経路も実行しない。
- 取引休日は直近完了営業日の同じ結果を確認するだけ。週次・年次も日々更新し、当日のファイルを残す。
- 長い停止後に過去日次帳票を全日分再作成する保証はない。最新の確認済み台帳から期間集計する。過去時点を再現できない資料を作らない。

登録/更新はプロジェクトで powershell -File scripts/register_forward_reports.ps1。-Preview で変更前に内容を確認できる。他の取得予約を変更しない。実発注・戦略更新・口座評価更新・データAPI取得・バックテストはこの処理に含まない。

## 実行と検証

.venv/Scripts/python.exe -B -X utf8 -m trading_system.research.forward_reports --asof 2026-11-26

通常の自動経路は --scheduled。日付省略時は保存済み営業日カレンダーから直近完了日を選ぶ。原本の日時・判断締切・ハッシュ・開始時台帳版・費用/資金/建玉の一致を検証する。BのSQLiteはread-only接続。A/Cは確定判断と決済・評価記録を突合し、Cの権利未照合等を未確認扱いにする。

集計はプロジェクトのPython、描画はCodex同梱PythonのReportLabを使用する。Codexアプリ起動は不要だが同梱ランタイムのインストールは必要。更新でパスが消えた場合はインストール済み同梱ランタイムを探す。MeiryoをPDFに埋め込み、SVGもMeiryoを指定する。

入力の集計前後SHAと内容ハッシュを保持し、描画コードのハッシュも再生成判定に含める。同一内容は再作成しない。公開前に3PDFのページ数とSVGを検証し、保存版に欠損があれば同じ固定パケットから再生成して既存SHAと一致を確認する。正常な同日の帳票を部分データで上書きしない。

内部の再現資料は data/forward-reports/runs/<日付>/<版>/packet.json と manifest.json、最新参照は data/forward-reports/latest.json。取得原本・台帳・レポートはGitHubに送らない。

実装委任はGPT-6.1 Sol High、重要レビューはGPT-6 Astra Highを指定した。実際に解決されたモデル名の独立照合はできない。
