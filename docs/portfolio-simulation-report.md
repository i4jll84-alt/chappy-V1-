# 複合戦略シミュレーションの作業報告

## 工程と担当

固定配分の判定基盤を合成時系列へ接続し、保有・費用・決済と戦略別の結果を追跡する。
第8章の継続工程であり、楽天証券RSSへの接続ではない。
設計・独立レビューは継続担当のGPT-6 Astra / High指定、通常実装は
GPT-6.1 Sol / High指定。比較処理・関連テスト・文書・統合検証は統括担当で、
統括担当のモデル・推論設定は未確認。比較処理も独立レビューを受けた。

## 実装内容

市場入力と、判断時点・寄付時点のリスク根拠を明示して処理する。
新規候補は次の寄付で実行を判定し、保有期間による決済・費用・残存保有を記録する。
各戦略の数量帰属を残し、複数戦略が同一銘柄に寄与した場合も追跡する。
シグナル型は既存の予測研究アダプターと共通だが、今回の標準実行は明示的に構成した
合成シグナルを使う。新しいモデル学習や学習モデルの収益検証を実行したものではない。
詳しい制約と比較条件は[設計](portfolio-simulation-design.md)を参照。

比較は複合実行と、各戦略のシグナルだけを残した個別実行で構成する。
全実行で初期資金・元の配分率・市場入力・費用・上限を保つ。配分率の再正規化や
成績による戦略選択はしない。停止した実行も保存し、比較全体を完了と扱わない。

## レビューで扱った点

空売りの約定価格が寄付の基準価格を下回ると、追加担保だけでなく売却代金の減少も
資金余力に影響する。価格差を含む事前予約と、実際の約定後を仮計算した状態の両方で
上限を検査する設計にした。手数料で純資産が下がる影響も後者で検査する。
また、保有中の担保計算でも制度情報の提供時刻・有効期限を検査し、未来の制度情報で
拘束額や停止を決めないようにした。

戦略別の損益・費用と口座全体の増減を照合し、許容丸め残差を超える場合は停止する。
残差は監査出力に残す。集計は初期の会計指標に限り、Sharpe等は未接続。
修正後のAstraによる最終レビューには、未解決の重大指摘はなかった。

## 未確認と次工程

実市場の利益、有意性、危機相場の実データ、動的配分の有効性は未確認。
実口座への発注・照合、実際の証券会社の保証金計算は対象外。
合成データでの会計・時点・状態遷移の確認と、実市場の投資有効性を区別する。
実市場への接続には引き続き、保存済みPITと時点別の制度・銘柄・企業行動・費用が必要。
新しいAPIキーや証券口座の操作は不要。
