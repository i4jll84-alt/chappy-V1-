# スイングの前向きペーパー比較

開始日は2026年11月16日。機械・サブエージェントそれぞれに現行・3条件追加の2口座を用意し、各口座は現金200万円・建玉なしで開始する。4口座は同じ元手を比較する別々の仮想口座。現金・取得原価・建玉は日をまたいで継続する。[固定した売買条件と過去の検証](swing-rule-evidence.md)を使う。

## 予約と日次ファイル

正規プロジェクトを作業ディレクトリとし、プロジェクトの仮想環境で `python -B -X utf8 -m trading_system.research.swing_forward` の後に次の操作名を指定する。保存先はGit管理外の `data/swing-forward/`。

| 操作 | 日本時間 | 記録 |
|---|---|---|
| init | 導入時 | 初期資金と空の建玉を initial.json に初回だけ保存 |
| morning | 平日07:55、東証営業日のみ | 直前営業日の23:59:59までの入力で機械判定を固定。sessions/対象日/preopen.json に順位・選外理由・買付・決済・資金を保存し、review-input.json に独立評価用の入力元を保存 |
| record-agent --answer 回答.json | 同じ日の09:00前 | エージェントの買付・決済・理由を agent.json に固定し、機械判定との差を保存 |
| evening | 平日20:10、東証営業日のみ | 日足始値で仮想売買、終値で時価評価、4口座を close.json に保存。当日と前営業日の東証別日証金残高・制限措置を公式検索から取得 |

金曜11月13日の夜は月曜初回の準備に使用する。日足と銘柄マスターは既存の18時タスクの受領票を確認し、必要時は営業日指定の swing_daily で補完する。日証金は同じ検索セッションで選定日のHTMLとCSVを保存し、別検索した7203東証の同日残高3項目と照合する。各資料に実際の保存時刻とハッシュを付け、締切後の取得を過去の入力に含めない。個別口座に関係のない収集停止は区別する。研究運用固有の手動停止は data/swing-forward/STOP。

## サブエージェントへの入力と回答

寄り前には [日米金利・ドル円・米国株・日経225先物の市場判断](market-context.md) も記録する。判断時点で利用できた指標と各群の見送り理由を固定し、引け後に元の各群と比較する。

2026年11月16日からは各買い候補に earnings_review を付ける。[決算予定の注記・提出形式・見送り効果の評価](earnings-review.md)に従う。引け後の評価担当は日次レビューの earnings_review から逸失利益・回避損失と比較口座の下落率、未評価件数を読み、繰り返す差がある場合だけ次の仮説を一つ記録する。

親は [呼出手順](trade-decision-agent.md) に従って trade_decision を呼び、当日の review-input.json とローカルの入力資料を渡す。親から機械順位や機械の判断を渡さず、独立した判定を先に取得する。コードはJ-Quantsの5桁表記。JSONの target と input_sha256 は review-input.json の同名値を転記する。groups に current・plus3 を各1件指定する。各群の buy は買付順位順のコード配列、sell は決済コード配列、reason は口座全体の判断理由、candidate_notes は銘柄コードをキーとする採否・保有・見送りの理由。買付・決済なしは空配列。該当銘柄例や固定済み機械出力を回答に転記して代用しない。口座ごとの明細と主要な見送りを記す。

紙上の口座運用に追加した共通条件は、1銘柄100株・同一銘柄の積み増しなし・同日の決済買い直しなし。上位5銘柄から既保有と概算現金不足を除き、下位では補充しない。寄付前の買付余力に予定売却の未確定代金を組み込まない。評価時の売買順は予定売却、買付順位順。始値がない買付・売却は未約定として記録し、残った期限到来建玉は次の営業日に再判定。信用入力欠測時は追加群の新規買付を保留し、既存建玉の決済予定は継続する。保有中の権利・日足行の欠落で会計を確定できない口座は要確認とし、終値がない場合の損益は未確定。税・配当は計上しない。

## 成績の読み方

close.json の fills に仮想約定・見送り、accounts に現金・建玉、metrics に累積実現損益・含み損益・総損益・費用・最大下落率、comparison に「エージェント対機械」「追加ルール対現行」の損益差を保存する。coverage は寄り前記録の有無、信用欠測、停止、要確認を示す。記録欠測の日は新規の指示を仮定せず、持ち越したポジションだけを評価する。比較する際は欠測日と判断相違を併記する。エージェントの原回答と機械判断の差を保存し、ルール・資金制約に抵触する提案は executable の skips に理由を残す。成績は仮想約定可能な指示で計算する。各日ファイルは一度確定したら再実行しても上書きしない。夕方を逃した場合は次回に前営業日の清算から順に再開する。取引所の寄付を過ぎた日の判断を事後に作らない。

PCがスリープ中・Codexが閉じている場合はローカル予約が寄付前に配信されないことがある。証券口座への注文、実資金移動、AI学習は行わない。

## ルールの見直しとGitHubの変更履歴

現行ルールを比較の基準に固定し、3条件追加を独立した改善案として前向きに追跡する。11月16日からの4口座はいずれも200万円・建玉なしで開始する。引け後の清算が成功した営業日ごとに、その日までの記録を再集計して `data/swing-forward/reviews/YYYY-MM-DD.json` に保存する。

- **継続口座全体**では現行・改善案の費用控除後総損益、実現損益と評価損益、最大下落率、買付・決済件数、欠測・停止日数を機械とエージェントそれぞれで読む。最大下落率は記録済みの終値評価に基づく。
- **信用情報がそろった日**の比較は、買付を判断した営業日を基準にする。機械・エージェントごとに、両ルールの寄り前判断・評価が記録され、締切までに信用の2時点を確認できた日を採る。対象日の仮想買付を実際の仮想決済まで追い、両群の全建玉が解消し6営業日の予定保有期間を過ぎた時点で、その日に始めた取引の費用込み損益と件数を比較する。翌日の信用欠測を理由に前日の取引を捨てない。両群とも買付ゼロの日は期間経過後に0円、未決済・期間未到来は保留。確定件数0の結果は未評価とする。信用情報の原本がそろっても銘柄個別の残高欠損や制限措置があれば追加群の選外理由に残る。投資金額と既存の持ち高も群ごとに異なるため、この比較だけで選定条件の因果効果は断定できない。
- さらに変更案が出たら、目的、現行との差、対象銘柄、売買・費用・欠測の扱い、評価指標、検証開始日と見直し条件を開始前にGitHubへ記録する。試行済みの期間を新案の成績に含めず、両群を同条件で以後の期間に並走させる。結果確認後にしきい値を調整した案は別版として次の未使用期間を使う。
- 見直しでは有利・不利の両方の結果、未確定件数、対象期間を添えて「採用候補・継続検証・見送り」とその理由を記録する。現在は継続検証。観測日数の不足や欠測による取引機会の差が大きい場合は判断を保留する。自動採用・実資金移行は設定していない。

ルール、実装、設定、検証方針を変更した際は、変更理由・適用開始日・確認結果を関連文書とともに対象ごとにコミットし、指定GitHubの main に同期する。採否の節目には検証集計と判断理由も記録する。日々の原本・仮想台帳・銘柄別明細・ログはローカルのGit管理外に保存する。
