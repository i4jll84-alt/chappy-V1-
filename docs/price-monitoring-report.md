# 保存済み株価取得の監視

Excel不要の運用監視の初期部分。既存DuckDBに保存したJ-Quants日次株価の取得状態を
読み取る。APIキーの読取、再取得、Raw・Parquetの生成、DB更新は行わない。

## 実行

```powershell
.\.venv\Scripts\python.exe -m trading_system.cli monitor-prices --code 86970 --from 2026-10-01 --to 2026-10-22 --max-age-hours 24 --output data/monitoring/prices-current.json
```

既定のDBは `data/jquants/catalog.duckdb`。別のDBは `--database` で指定する。
`--max-age-hours` は必須の正の有限数で、取得完了から許容する経過時間を明示する。
例の24時間は機能検証用の条件であり、提供元の更新予定や運用に適切な値と認定したものではない。
休日・配信時刻を踏まえた自動スケジュール判定は実装していない。

既定の観測時刻は実行時のUTC。`--observed-at` はタイムゾーン付き日時を指定できるが、
過去時点のDBや提供元状態を復元するものではない。現在保存されている状態を読む。
出力はJSON形式で、DBのディレクトリ外に限定し、元DBや保存データの上書きを防ぐ。

終了コードは0=`observed`、3=`attention`、2=入力・読取エラー。
0は対象範囲の監視で注意項目がないことに限り、実運用への準備完了ではない。

## 判定

- コードを正規化し、コード・開始日・終了日が完全一致する取得ジョブを対象とする。
- 開始日時とジョブIDで最新を選ぶ。最新が失敗・未完了・未来時刻でも、古い成功へ戻さない。
- 失敗、実行中、取得のみ完了、空結果、品質異常、残るページカーソルを報告する。
- 完了確定時刻からの経過時間を検査し、期限超過と未来時刻を区別する。
- ページ数・取得行数・観測行・参照バージョン・対象キーの矛盾を検出する。
- 保存済みの品質情報とHTTP試行結果を集計する。例外本文や認証情報は表示しない。
- 過去の取得状態は別集計とし、過去に失敗しただけで新しい成功を失敗扱いしない。

無約定日の行、同じ内容の再取得による旧版の再利用、同一キー重複の品質警告を区別する。
異常な行を削除したり補完したりしない。DuckDBは読取専用トランザクションで確認する。
互換性のない同時接続や読取不能を、書込み接続への切替えで回避しない。

## 制限

取得完了が新しくても、株価の対象日が古い場合がある。対象日最小・最大は表示するが、
この機能だけでは必要な全営業日の取得や、今日の市場データの提供完了を保証しない。
期間の営業日照合は既存の[カバレッジ監査](coverage-audit.md)を利用する。
Rawファイル実体やParquetの再検証、OHLCの品質規則の再実行、実API疎通は対象外。
公表時刻・提供元更新時刻を取得完了時刻から推定しない。
ハッシュは読んだメタデータの組合せを表し、元ファイル実体の正当性を認証するものではない。
常駐監視・自動通知・自動再取得・注文処理は含めない。

## 保存済み実データによる確認

2026年10月23日に、86970の10月1日〜22日の保存済み実API取得データを読んだ。
最新ジョブは完了、15観測・15銘柄日キー、重複0、参照欠落0、キー不一致0。
取得完了から約3.27時間の時点で、24時間条件では注意なし（終了0）、
1時間条件では期限超過（終了3）だった。どちらも今回のAPI接続を伴わない。

固定観測時刻・24時間条件で2回出力したJSONはバイト単位で一致した。
3回実行前後で元catalogのSHA-256は不変。
結果はGit対象外の `data/monitoring/prices-current.json`、`prices-repeat.json`、
`prices-strict.json` に保存した。
