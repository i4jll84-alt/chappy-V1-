## 保存方式と実行

一括CSVは調整済みOHLCを含まない。未調整価格・AdjFactor等を文字列として保持し、
空欄・先頭ゼロ・原本の列を維持してParquetへ変換する。調整系列は別保管先へ作成済み。
APIとの精度・丸めの差は未解決で、実データの損益計算には未接続。詳細は [調整系列の検証](adjusted-history.md)。
JSONは元payloadを保持し、ページ保存・行系譜・checkpointを同じSQLiteトランザクションで確定。
一括ファイルの更新日時・サイズが変われば別バージョンとして保存する。
保存済みJSONジョブは再実行時にスキップするため、過去の訂正を巡回する機能ではない。

不明な公表日時・実提供日時はnull。HTTP Last-Modifiedはヘッダーとして保存し、
公表日時へ転用しない。初期PITは取得完了+1秒以降のみ利用できる。
今回の取得では過去の判断時点を復元できず、現行戦略・実データバックテストへ自動投入しない。

~~~powershell
# 作業場所: C:\Users\i4jll\Documents\ChatGPT\個別株自動売買ツールV1
# 同じ取得処理が動作していないことを先に確認する
.\.venv\Scripts\python.exe -m trading_system.history_download --phase all
.\.venv\Scripts\python.exe -m trading_system.history_audit --output data\jquants\history\audit-latest.json

# 無料資料の更新取得
.\.venv\Scripts\python.exe -m trading_system.free_market

# 定期確認: 最新の平日08:00以後の取得が済んでいれば通信しない
.\.venv\Scripts\python.exe -m trading_system.free_market --due
~~~

日付指定は --start YYYY-MM-DD --end YYYY-MM-DD。日付APIに適用する。
一括ファイルは契約で取得可能な一覧全体を対象とする。--max-itemsは試行用取得上限。
--phase bulkの完了は一括段階だけの完了。全データ完了とは区別する。
J-Quantsは約100リクエスト/分以下、429は120秒待機して有限回再試行。
停止ファイルは data/jquants/history/STOP または data/free-market/public/STOP。
再開時は理由を確認してSTOPを解除する。スリープ・終了からの自動復帰は設定していない。

無料資料は公式ページに掲載されたリンクとアーカイブ選択肢だけを追う。
HTTPS・提供元と対象パスを限定し、転送には追従しない。
元ファイルとCSV全行/HTML表を保存し、XLS/XLSX/PDFは原本保存のみ。
HTTP更新確認と内容ハッシュで同一内容を識別し、更新前の原本も保持する。
最大1,200資料/巡回、要求間隔0.6秒。429/503では巡回を中断し失敗を記録する。
保存はSQLiteで取得記録単位に確定。再巡回で過去の取得記録を消さない。
取得データを公開GitHubへ再配布しない。

## 定期取得

2026-10-31の最新指示により、通常の取得時刻は **平日08:00（Asia/Tokyo）**。
月〜金が対象で、祝日を別途除外する設定ではない。従来の毎時00分・30分のチャット起動は廃止。
Codexのこのチャットの予約「日証金・JPXの無料データ取得」（ID jpx、ACTIVE）を
平日08:00へ更新した。最新の平日08:00以後に開始し、正常完了した巡回があれば、
`--due` は already_acquired として通信せず終了する。失敗や途中終了は取得済みとしない。
遅い起動・深夜・翌日・週末も、直前の平日08:00を判定基準にする。
これは取得時刻の基準であり、各資料の公表時刻や対象日が08:00という意味ではない。

ユーザーが指定した「再開」は **PC復帰ではなくCodexアプリの起動**。
補完用のWindowsタスク `JPX-FreeMarket-CodexStartup` を通常ユーザー権限で登録した。
1分間隔でローカルのアプリ起動状態だけを確認し、チャット・モデルは起動しない。
アプリ本体の起動から30分経過後の最初の確認で、未取得なら `free_market --due` を実行する。
OSの実行遅延を除いて30〜31分後が目安。取得済みなら通信しない。
同じアプリ起動については1回だけ処理し、失敗を毎分再試行しない。
失敗時は次の通常予約、次のアプリ起動後、または明示的な再実行で再試行できる。
既に巡回中なら重複起動をせず、終了後の取得結果を再確認する。STOPは解除しない。

現在のアプリは `OpenAI.Codex_.../app/ChatGPT.exe`。同一Windowsセッションの
本体だけを選び、rendererやCLI、別ユーザーのプロセスを対象にしない。
起動時刻は本体プロセスの生成時刻であり、最小化からの表示や、バックグラウンドで
動作したままのウィンドウ再表示では30分の計時をリセットしない。
アプリを閉じた場合は本体が起動している間だけ補完判定を行う。
Codex側の予約が遅れて届き、その日の08:00より後にアプリが起動していた場合は、
即時取得せずWindows側の30分後補完に任せる指示を保存した。

補完の状態は `data/free-market/public/scheduler/startup-status.json`。
取得開始時の出力と失敗は同じschedulerフォルダーの固有ログに保存する。
state・exit_code・result内のissuesと更新件数を確認する。
待機や処理済みの確認では直前の失敗記録を上書きしない。
原本・DB・ログ・タスクの実機情報はGitHubへ送らない。
