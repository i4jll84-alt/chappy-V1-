# 第8章: 固定配分・リスク判定の初期基盤

## 工程と範囲

第3段階の初期研究基盤に続き、短期・スイング・中期の候補を固定配分で統合する。
合成した口座・制度・リスク情報を明示し、集中・余力・損失・相関を判定する。
実口座への接続、実注文、複合戦略の実市場での有効性評価は対象外。
詳細は[設計](portfolio-design.md)を参照。

## 使用した担当モデル

- 設計・独立レビュー: GPT-6 Astra / Highの指定で継続している担当。
- 通常実装: GPT-6.1 Sol / Highの指定で継続している担当。
- 研究結果の接続・関連テスト・文書・統合検証: 統括担当。モデル・推論設定は未確認。

指定設定の記録であり、実行サービス内部のモデルを別途測定したものではない。
統括担当の接続部分も設計担当が独立レビューした。

## 実装

`src/trading_system/portfolio/`に入力モデル、固定配分、リスク判定、合成入力、
予測結果との接続をまとめる。CLIは取得用APIや認証情報を必要としない。
合成研究の予測を接続する際は結果・シナリオ・モデルのハッシュと判断時刻を確認し、
予測の符号だけを使う。資金量を予測の大きさから決めない。

## 未確認と制限

実市場の時点別業種・相関・口座余力・貸株在庫は未接続。
リスク入力の数値は合成例であり、実運用に適した上限や担保率を検証したものではない。
損失の制約は指定したストレス仮定に対する計算であり、現実の最大損失を保証しない。
本処理だけで約定、決済、緊急縮小、注文取消や再試行の安全性を保証しない。
複合戦略の期間全体のバックテスト、市場環境に応じた動的配分は未実装。

## 次工程とユーザー操作

この判定を複合戦略の時系列シミュレーションへつなぎ、保有・予約・決済の推移を含めて
単独戦略と同じ条件で比較する。実市場への接続には継続して時点別根拠の整備が必要。
この合成検証を動かすためのAPIキー追加や証券口座の操作は不要。
重要な設計・監査はAstra High、通常実装はSol Highを推奨する。
