# バックテストの制度確認と入力の扱い

確認日: 2026-10-23。制度の存在を確認するための資料であり、過去の全銘柄・全日付の
ルール履歴、楽天証券の口座別条件、約定可能性を取得できたという意味ではない。

| 公式資料 | 確認した点 | シミュレーションへの反映方針 |
|---|---|---|
| [JPX 売買単位](https://www.jpx.co.jp/equities/trading/domestic/03.html) | 内国株の100株統一は2018-10-01。現在の単位を過去すべてに適用できない | 売買単位をシナリオの明示入力とする |
| [JPX 呼値](https://www.jpx.co.jp/english/equities/trading/domestic/07.html) | 銘柄区分・価格帯によって呼値が異なる。2027-03-01の方式変更も公表されている | 現行の固定表を過去・将来へ無条件に流用しない。検証用の呼値と実制度を区別する |
| [JPX 制限値幅](https://www.jpx.co.jp/english/equities/trading/domestic/06.html) | 基準値段による制限と値幅拡大の例外がある | 上下限価格と約定可能数量を別々に扱う。価格が範囲内でも約定可能とは断定しない |
| [楽天証券 信用取引の費用](https://www.rakuten-sec.co.jp/web/domestic/margin/commission.html) | 貸株料・品貸料・管理費等は別項目。取引区分や口座条件で扱いが異なる | 入力費用を明示し、模擬値を楽天証券の実請求額と呼ばない |
| [楽天証券 信用取引の基本ルール](https://www.rakuten-sec.co.jp/web/domestic/margin/rule/ground_rules.html) | 保証金、権利処理、信用取引区分等の条件がある | 在庫・規制・権利・保証金の履歴不足をゼロ費用や制限なしで埋めない |

日次OHLCと出来高だけでは寄付の板、注文順位、在庫、過去の規制、権利処理や費用の
確定時点を復元できない。合成シナリオの約定・会計テストと実市場の検証を区別する。
実データのバックテストには、判断時点に利用可能だった情報に加え、約定と権利処理の
根拠が必要となる。第1段階の初回取得以前を再現できるという主張はしない。
