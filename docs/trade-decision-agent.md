# ペーパー取引の判断を依頼する

このプロジェクトをCodexで開き、`trade_decision` を名指しして依頼する。設定は [trade_decision.toml](../.codex/agents/trade_decision.toml) にある。GPT-6 Astra、高推論で、ローカルの観測記録・当日銘柄マスター・仮想建玉を読み、銘柄ごとに判断を返す。

> trade_decision サブエージェントで、直近の引け後時点のスイングを資金200万円、新規の仮想口座（建玉なし）で判定してください。現行ルールと3条件追加案の候補、翌営業日の予定、見送り理由を示してください。

保有株を判定するときは仮想台帳の所在、またはコード・数量・買付日・残余現金を渡す。返答は「買い候補・保有・決済候補・見送り」。寄付前の候補は予定として扱う。ルールを指定しない場合は現行を主判定とし、3条件追加案は別の同額の仮想口座で比較する。どちらも現時点の研究用ルールである。

判断には価格・信用情報の対象日と利用可能時刻、仮定した手数料・スリッページ、順位・数量を添える。信用情報が足りなければ追加群の判定を保留し、独立して判定できる現行群は続ける。過去の検証の強みと限界は [スイング売買ルールの比較](swing-rule-evidence.md) にある。

手動照会に加え、2026年11月16日からは [前向きペーパー比較](swing-forward.md) の寄り前予約でもこのエージェントを使う。回答はペーパー取引案で、ブローカーや台帳への書き込み処理は呼び出さない。Codexのプロジェクト単位のカスタムエージェント定義を利用する。実行権限は親セッションから継承される。[OpenAI Docsのサブエージェント仕様](https://learn.chatgpt.com/docs/agent-configuration/subagents)


役割名を直接指定できないクライアントでは、親のCodexが [AGENTS.md](../AGENTS.md) に従い、定義のモデル・推論強度・指示を明示して同じ役目のサブエージェントを呼ぶ。
