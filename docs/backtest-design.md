# 第2段階: 再現可能なバックテスト基盤

第1段階の最小到達目標の確認後、2026-10-23のユーザー指示で着手した。
対象はシミュレーションと検証であり、証券会社接続・実注文・AI学習は含まない。
初期実装は既存のPython・Pydantic・DuckDBに、標準ライブラリのDecimalを組み合わせる。
限定した日次約定と会計を手計算で監査できることを優先し、候補のBacktraderやVectorBTを
新規依存として追加しない。これらのライブラリの全面的な性能比較を実施したという意味ではない。

## 入力の信頼境界

最初の実行対象は明示された合成シナリオとする。合成価格・在庫・費用による成績は
実市場での有効性の証拠ではない。価格だけをJ-Quantsから持ち込み、不明な制度や在庫を
合成値で補って実データ検証と表示する機能は提供しない。

保存済み実株価には、検索条件を完全一致させた読取り専用PIT事前検査を設ける。
判断時点までに確定した検索と、その確定から1秒後の利用可能条件を満たす版だけを使う。
必要な銘柄・日付の行がなければ失敗とし、最新テーブルや調整済み系列へ切り替えない。
株価の事前検査が通っても、過去の投資対象・取引ルール・権利・在庫の根拠が揃ったとは
みなさない。現在の初回取得以前の価格を当時既知のデータとして売買判断に使えない。

制度の確認元と、現在の制度を全期間に流用しない理由は
[公式資料の確認](backtest-official-sources.md)に記録する。

## 判断・注文・約定

戦略は判断時刻までに利用できる過去の情報から注文を作る。終値を見た注文は同じ終値で
約定させず、必ず後のセッションの寄付で評価する。将来の価格・流動性は約定処理だけが
参照し、戦略の入力とは分離する。基準戦略は固定数量と保有期間を使う単純なものとする。

現物買い/売り、信用新規売り/返済買いを区別する。売買単位、呼値、スリッページ、価格の
上下限、売買停止、約定可能数量、信用売り許可と在庫を入力で明示する。約定しなかった
注文には理由を残す。日次出来高から寄付での約定可能数量を逆算しない。

シミュレーションの信用売りは保守的な現金担保方式とし、売却代金を自由な追加投資資金と
みなさない。楽天証券の保証金・受渡・追証の完全再現ではない。対応していない担保不足の
処理は成功扱いにせず終了する。

## 会計と権利処理

会計はDecimalで計算し、金額を文字列で保存する。現金、ポジション、未決済の権利、
手数料、貸株料、品貸料を区別し、注文・約定・台帳・評価額を追跡できるようにする。
価格に含まれるスリッページを損益から二重控除しない。

分割・併合は明示イベントで数量と取得単価を変換する。端株処理の根拠が必要な場合に
架空の価格で売却しない。配当等は権利発生日の保有を根拠に債権・債務を記録し、支払日に
決済する。調整済み株価に同じ権利処理を重ねない。複雑な権利行使など未対応のイベントは
黙って無視しない。
同じ銘柄・同日の分割と現金権利の併発、全保有が1株未満になる併合は未対応として拒否する。
分割後に売買単位に合わなくなった保有は、通常注文では約定せず残り得る。
保有期間の上限は決済注文を出す条件であり、約定の保証ではない。

## 評価と探索履歴

損益・コスト・売買回数・保有期間・買い/売り別集計と、資産曲線のリターン・リスクを
記録する。短い合成期間で算出した年率値を運用見込みと解釈しない。分母がゼロ、比較対象が
ない等の指標は定義に従いnullとして理由や制限を明示する。未決済保有を最終日の価格で
強制売却した実現損益に置き換えない。
合成比較指数との差は実TOPIX超過リターンとは区別し、実TOPIX指標はnullとする。
信用売りの代金を含む会計上の現金と、担保拘束後に利用できる現金も分けて表示する。
会計はDecimalだが年率リターンのべき乗は浮動小数点近似であり、厳密な桁比較の再現性は
同じPython・依存関係の実行環境で検証する。

`evaluation.walk_forward_splits`は順序づけ済みセッションのインデックスを受け取り、
拡大型の訓練期間、重複しない検証期間、最後の未使用期間を分ける。ラベルの終了時点が
検証開始に到達する訓練サンプルを除き、必要な直前の空白期間も設ける。未来側の訓練を
使わない。また検証ラベルが最終未使用期間やその直前の空白期間へ到達するサンプルも除く。
この方式は、検証後のエンバーゴを持つ一般的な交差検証とは区別する。
日付の整列、対象データとの対応は呼出し側の責務である。

`ExperimentRegistry`は入力・候補パラメータを固定したmanifestをハッシュで識別し、
成功・不採用・失敗の探索記録を保存する。同じmanifestの最終評価は評価関数の呼出し前に
消費済みにし、例外や中断でも再評価の権利を戻さない。最終評価を開始した後は探索を
追加できない。ローカルの単一書込み用途であり、手動編集や新しい実験IDで同じ期間を
繰り返し使うことまで防ぐ仕組みではない。実市場の急変期の検証はまだ実施していない。
分割と記録はPython APIで提供し、自動のパラメータ探索や学習は行わない。

## 再現性の確認

シナリオ、戦略設定、エンジン版、実行上の仮定、注文、約定、台帳、資産曲線を保存する。
実行時刻やランダムIDを計算結果へ混ぜず、同一入力の結果ハッシュ一致を検証する。
異常系・権利処理・信用コストは手計算可能な小さい例と突き合わせる。
情報漏洩監査は、未来データを変えても過去の注文が変わらないこと、判断以前に利用不可の
行を受け入れないこと、同じ終値で売買しないことを対象とする。
