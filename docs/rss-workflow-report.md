## 3. 実装した機能

`--workbook` は有限回の既存Excel読取後、実行記録の確認、Raw・DB保存、Parquet生成、
ストア監視、元観測との照合を順番に行う。読み取りは既存の `rss_live.observe` を使い、
回数・間隔・タイムアウトの上限も引き継ぐ。値不変の注意設定は今回の一括CLIに含めない。
`--run` は既存観測だけを使用し、Excelに接続しない。

summary.jsonと0始まりの連番が揃わない実行は、新たなDB保存前に停止する。
正常に記録された取得失敗・品質注意は消さずに保存し、最後も注意を返す。
各工程の開始と完了を `data/rss-workflows/<id>.json` に原子的に記録する。
工程失敗時は後続へ進まず、完了済み工程と失敗工程を残す。例外本文や元ブックパスは記録しない。
観測後の保存・出力失敗は `--run` で再実行できる。新しい市況読取や自動修復を実行しない。
再実行時は同じ取込済み記録を重複させず、必要なParquetを再生成する。

接続状態unknown、鮮度検証falseを維持する。実行完了は各処理の完了であり、
市場の鮮度や実運用準備完了の意味ではない。発注・セル変更・再計算・再接続・常駐は行わない。

## 9. 既知のリスク・制限

単一実行で使用し、別の観測・保存・監視を同時に動かさない。
工程全体を1トランザクションにはしない。取込済みデータは後続失敗でも残る。
工程記録の書込自体に失敗した場合、最新状態を記録できないことがある。この場合は失敗を返す。
強制終了では記録がrunningのまま残る。これは稼働中を証明しない。
観測途中の例外では実行IDを受け取れない場合がある。元観測フォルダーを保持して調べる。
summaryの集計全体やRaw内容は後続の既存監視が再検査するため、異常が取込後に判明する場合もある。
照合は対象実行の親ディレクトリ全体を使うため、過去の未完了・未取込でも注意になる。
自動再開・削除・バックグラウンド実行・市場時間の自動判定は実装していない。
