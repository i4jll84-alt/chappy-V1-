# モック注文管理の作業報告

## 工程と担当

第9章の初期工程として、実発注しない注文状態管理と障害試験を実装する。
設計・独立レビューは継続担当のGPT-6 Astra / High指定、通常実装は
GPT-6.1 Sol / High指定。統括担当は文書・別プロセスによる確認・統合検証を担当し、
統括担当のモデル・推論設定は未確認。

## 対象

注文側とモック側の状態を別々に永続保存し、送信応答の喪失、再起動、取消と約定の競合を
再現する。同一注文の再要求で実行を増やさず、不明な状態を勝手に未受付へ戻さない。
入力・判定・状態変更・照合の履歴を保持する。
詳しい動作と制限は[設計](mock-execution-design.md)を参照。

## レビューと制限

照合の読取失敗でも停止を永続化し、残高が一致していても未知の未約定注文があれば
新規送信を止めるようにした。拒否された要求の監査記録も、状態更新のロールバックとは
別に残す。確定済み状態の変更、同じ約定IDの内容変更、過去の約定の削除は拒否する。
修正後のAstraによる最終レビューに未解決の重大指摘はなかった。

第9.3節の12安全項目を、固定条件のモック範囲で検査した。
部分約定後の残数量の資金拘束には固定手数料を保守的に残す。
売却・返済でも最大注文数量・金額と現在の現金余力下限を適用し、資金不足からの
強制決済を保証しない。詳細な境界は設計書のとおり。
