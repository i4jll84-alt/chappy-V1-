## 許可する通信

実装は`src/trading_system/brokers/mufg_esmart/connection_check.py`。
通信先は同じPCの`http://localhost:18080/kabusapi`だけに固定し、次の2種類以外を
HTTPトランスポートで送信前に拒否する。URLを自由に指定する引数は設けない。

1. `POST /token`: APIパスワードからトークンを1回取得。
2. `GET /board/7203@1`: 東証7203の株価・板を1回取得。既存RSSと同じ接続確認用銘柄。

プロキシ環境変数を使用せず、リダイレクトを追わず、自動再試行もしない。
各通信のタイムアウトは5秒、受信量は1MiBまで。受信の経過時間も検査する。
本番用ポートから実データを取得するが、注文用URLや注文メソッドは許可しない。
検証用ポート18081の応答を実接続成功に代用しない。

公式仕様上、株価・板の照会によりAPI登録銘柄リストに対象銘柄が追加される。
今回のコードは登録解除を呼ばない。また、新しいトークンの発行は以前のトークンを無効にする。
複数の利用プログラムがある場合は、この性質を考慮して実行する。

## パスワードと保存

```powershell
.venv/Scripts/python.exe -B -m trading_system.brokers.mufg_esmart.connection_check --prompt
```

PC上の入力画面へ、本人がアプリで設定した**本番用**APIパスワードを入力する。
検証用パスワードは18080の認証には使わない。本番用でも、このコードは取得専用である。
入力は伏字とし、コマンド引数、チャット、環境変数、ファイルには保存しない。
認証応答、トークン、認証ヘッダーも保存・表示しない。取消なら通信せず終了する。

取得した板の応答本文は`data/mufg-esmart-checks/<run-id>/board.raw.json`にそのまま保存。
同じフォルダーの`report.json`に取得開始・完了日時、HTTP状態、SHA-256、検査結果を保存する。
再実行は新しいフォルダーを作り、以前のデータを上書きしない。
認証情報の混入を検知した本文は保存せず、その理由だけを記録する。
応答量・通信時間の制限で中断した取得を、全量保存済みとは扱わない。
これらのデータ・ログ・検証証跡はGitHub送信対象外。

単発の診断用スナップショットであり、DB・Parquetへの日次取り込み、訂正判定、
共通アダプターへの接続、ペーパーの仮想約定はまだ実装・検証していない。

## 品質と確認の意味

銘柄・市場、現在値・現在値時刻、売買各10段の価格・数量を検査する。
nullや異常値は補完せず、元の応答と注意を残す。nullを無約定の証明としない。
認証・応答の成功と値の品質を区別し、不足があれば`connected_with_attention`とする。
銘柄・市場が一致しない場合は接続確認を失敗にする。

公式仕様ではBid/Askの名前と日本語で説明される売買方向が逆になっているため、
この確認は明示的な`Sell1..10`・`Buy1..10`を使う。共通板モデルへの変換は行わない。
`CurrentPriceTime`は現値の時刻として記録する。板全体の提供元更新日時や公表日時は
分からないためnullとし、取得時刻で代用しない。厳密な鮮度と実市場約定は未検証。

## 継続取得と共通処理（2026-10-29追加）

利用者の指示を受け、三菱UFJの株価・板に限る継続取得と復帰処理を追加した。
認証と東証7203の板GETだけを許可する既存トランスポートを再利用する。
注文・訂正・取消・口座照会は実装せず、ペーパーの発注先や既存戦略も変更しない。

- `brokers/mufg_esmart/market_data.py`: メモリー内のパスワード・トークン、取得通信。
- `brokers/mufg_esmart/adapter.py`: 共通`BrokerAdapter`の株価・板・接続状態を実装。
  registryの`vendor_adapter(..., enabled=True, market_data_client=client)`で明示的に作る。
  デフォルト生成は従来の無接続状態。実データは`evidence=observed`として扱い、
  模擬市場データへ偽装せず、既存の仮想約定や注文Routerへ自動投入しない。
- `brokers/market_data.py`: 共通の取得ループ、待機、停止、保存・照合。
- `storage/market_data.py`: Raw、DuckDB、checkpoint、Parquet。
- `brokers/mufg_esmart/capture.py`: 本人が入力して起動する取得専用入口。

### 操作

```powershell
# 本人が本番用APIパスワードを伏字画面へ入力。通常は本日16時まで取得。
.venv/Scripts/python.exe -B -X utf8 -m trading_system.brokers.mufg_esmart.capture --prompt

# この取得プロセスだけに2回の通信失敗を発生させ、再接続を確認して取得を継続。
.venv/Scripts/python.exe -B -X utf8 -m trading_system.brokers.mufg_esmart.capture --prompt --verify-reconnect

# 停止要求。現在の読み取りが終わった後、保存・照合して終了。
.venv/Scripts/python.exe -B -m trading_system.brokers.mufg_esmart.capture --stop

# 通信しないRaw取り込み復旧・Parquet再生成。既存取得プロセスと同時には動かさない。
.venv/Scripts/python.exe -B -m trading_system.brokers.mufg_esmart.capture --recover
```

`--root`の既定値は`data/mufg-continuous`。`--max-seconds`で短時間の確認も可能。
`STOP`がある間は開始せず、停止要求を自動解除しない。再開時は利用者が停止完了を確認し、
対象保存先の`STOP`だけを除いて改めて起動する。履歴やDBは削除しない。
同じ保存先への二重起動は共通のOSファイルロックで、入力画面を出す前に拒否する。
起動時・パスワード入力後・再試行待機中に元の起動日の16時期限を確認する。
16時以降の起動や翌日へのスリープ復帰では、新しいAPI取得を始めず保存・照合する。
OS常駐登録、定期通知、APIアプリの自動起動・自動ログインは行わない。

### 切断・品質・再認証

- 通常は読取完了後5秒待機。通信失敗、429、500、503は5/10/20/40/60秒を上限とした
  待機で再試行し、429は最低30秒待つ。連続6失敗で停止する。
- 接続の再試行はHTTPクライアントを作り直す。古い株価・板は切断の時点で破棄する。
  APIトークンが有効なら再利用し、毎回発行しない。
- 板の401/403では、メモリー内パスワードによる再認証をセッション内1回だけ試す。
  再認証失敗、再度の認証切れ、その他の非一時的エラーでは停止する。
  アプリのログアウトから無人で復帰できるとは扱わない。
- 再開条件は当日・現値時刻が取得完了から60秒以内・時刻の逆行なし・有効な売買各10段。
  3件連続で確認できるまで共通の`quote`/`board`は値を返さない。欠損・0数量・不正な板順序・
  売買の交差はRawと注意を保持し、勝手に修正しない。昼休みや無約定で古い現値になる場合も
  保守的に待機する。この判定は「データ欠損」や「無約定」の断定ではない。
- 共通`Quote.source_updated_at`には公式の現値時刻を入れる。板全体の更新日時・公表日時は
  不明なのでnull。`known_at`/`available_at`は取得完了後。厳密な鮮度は未検証のまま。
- 共通板のbidsは`Buy1..10`、asksは`Sell1..10`。公式のBid/Askフィールド名の逆転を回避。
  数量は整数の値だけを受け入れ、丸め・補完しない。

### 保存・復旧

`raw/<session-id>/<sequence>.json`に記録と応答の元bytesをBase64で可逆保存する。
認証本文は保存しない。板本文にパスワードやトークンが混入した場合も本文を保存せず停止する。
失敗の記録、注意、制御した通信遮断の印は保持する。Rawファイルは上書きしない。
同じ本文を再取得した`identical`と変更スナップショットを分け、前版ハッシュを保持する。
板の変化と提供元の訂正を判別する情報がないため、変更は`revision_unverified`とする。
古い版を削除せず、過去時点に取得していない価格を再現できるとは扱わない。

取得記録とcheckpointは同一DuckDBトランザクションで確定する。
Raw保存後の中断は次回起動時に順番を検査して取り込む。保存失敗を正常終了にしない。
12回の通信ごとと終了時にRaw・DBの内容とcheckpointを照合し、Parquetは全セル・スキーマを
比較した新しい世代だけを公開する。旧世代と欠けた旧セッション終了記録は保持する。
復旧時に過去セッションの正常終了記録や仮想約定を作り足さない。
`status.json`は現在状態、`sessions/<id>.json`は終了結果。取得中のDBを別プロセスで開かず、
状態ファイルを見る。データ、ログ、パスワードをGitHubへ送信しない。
