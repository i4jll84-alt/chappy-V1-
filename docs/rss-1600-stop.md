# RSSの16時停止と保存データの復旧

実装・確認日: 2026-10-27。作業場所はローカルの個別株自動売買ツールV1。

## 普段の操作

1. 営業日8:30ごろ、PC・マーケットスピードII・Excelを起動する。
2. 本人がログインし、RSSを「接続中・発注不可」にして「RSS接続確認して開始」を開く。
3. 取得中はPCを稼働させておく。プログラム自身がAsia/Tokyoで16時を判定する。
4. 16時以降は新しい読取を開始しない。処理中の読取を終えてRaw・DB・Parquetを保存し、
   全件照合して取得プロセスを終了する。開始画面の保存・照合完了表示を待ってアプリを閉じる。

途中で停止するときは赤い「RSS常時取得を停止」を使う。
PowerShellのウィンドウは完了表示用に残るが、取得Pythonプロセスは終了する。
定期チャット通知やCodexの稼働を16時停止の条件にしない。
毎朝の自動起動、PC電源断、Excel・証券会社アプリの終了は行わない。

## 時刻と後処理

RSSと段階AのLifecycleはruntime.models.daytime_deadlineを共有する。
RSSの手動起動日は曜日にかかわらず16時を終了期限とする。
市場の営業日を推測する実装は追加していない。取引カレンダーを使う日次ジョブ・戦略の
営業日判定は既存の段階Aにあり、実RSSの日次候補作成との統合は未実装。

- 16時以降の直接起動はpostprocessing。Excel読取をせず、残存Rawの
  取り込み、Parquet書き出し、仮想台帳照合だけを実行して終了する。
- ショートカットは15:59以降、事前読取の所要時間を考慮して同じ後処理へ移る。
- 寄り前・場中の起動は最初に残存Rawを回収してから取得する。
- 次の日までスリープしても元の起動日の16時期限を保持し、復帰時に保存・終了する。
  翌日の取得は利用者が改めて起動する。
- オフライン復旧では過去のデータから仮想約定を追加しない。実発注は常に無効。
- 未完了だった取得のsummaryや旧セッションの正常終了記録を作り足さない。
  復旧成功は新しいセッションに記録する。

16時ちょうどのプロセス終了は保証しない。進行中の読取には標準10秒のタイムアウトがあり、
その後の保存・全件照合は保存量とPC速度に依存する。
停止途中はstatus=stoppingとphase=saving_parquetまたはverifying_saved_dataを表示・保存する。
scheduled_stop_at、stop_delayed、delay_reason、stop_delay_secondsで遅延を確認できる。
PCがスリープ・電源断中の時刻に処理を実行することはできない。

## 保存失敗と履歴

保存失敗・ハッシュ不一致・未取り込み残存・仮想残高不一致ではnormal_exit=falseとする。
CLIはエラー終了し、ショートカットに保存未完了を表示する。
新しい取得や自動再起動は行わず、保存済みRaw・古いParquet世代・失敗履歴を保持する。
必須保存に失敗したとき正常終了を装わず、強制終了や電源断は実行しない。

過去の読取エラー、株価鮮度未検証、欠落summaryは注意履歴として保持する。
データの整合性確認と、当時の取得成功・正常終了を区別する。
以前の1万行・1千runまでという監査上限を除き、Rawを順次検証し、
公開ParquetとDBを全件比較する。1ファイルのサイズ上限等は維持する。

## 実行した検証

外部通信・実口座接続を行わず、固定データ・仮想時計で検証。

~~~powershell
.venv/Scripts/python.exe -m pytest tests/test_rss_shutdown.py tests/test_rss_continuous.py tests/test_rss_live.py tests/test_rss_monitoring.py tests/test_rss_coverage.py tests/test_runtime_lifecycle.py -q --basetemp .t1600b --junitxml=data/rss-1600-targeted.xml
.venv/Scripts/python.exe -m pytest -m 'not live' -q --basetemp .t1600full --junitxml=data/rss-1600-full.xml
~~~

関連138件成功（24.88秒）、全回帰1,053件成功・live5件除外（86.50秒）。
初回テストの模擬IDの大小文字と固定時刻指定を修正して再実行した。
16時到達中の読取、待機中の到達、開始直前の競合、日をまたぐ復帰、
16:10/19:00/22:00起動、二重取り込み防止、復旧による仮想約定禁止、
保存・監査・最終状態ファイル保存の失敗、旧監査上限を越える10,010件・1,001runを検証した。

実際の夜間起動はWindows PowerShell 5.1で開始スクリプトを実行し、
後処理のみで保存・正常終了したことを確認した。
最初は実行ポリシーの未指定で拒否されたため、起動プロセスだけRemoteSignedを指定した。
PC全体の実行ポリシーは変更していない。ショートカットのアイコンは維持した。

実時刻16時の連続運転での停止は次回確認対象。PCの時計や設定を変更して試験していない。
市場の実データに接続した日次ジョブ全体、モデル再学習、実口座の注文処理は今回の対象外。
