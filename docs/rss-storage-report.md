## 3. 実装した機能

実行IDとサンプル番号を観測の識別子として扱う。入力JSONのバイト列をSHA-256別に
Raw保存してから、Raw内の数式・値・銘柄・時刻を再検査する。保存済みの正規化値や
鮮度フラグは信用せず再生成する。価格は精度を落とさない文字列で保持する。
不正JSON・日時不整合等はRawを保持して拒否記録にする。異常値は補完しない。
観測と取込済みチェックポイントは同じDBトランザクションで確定する。

同一ID・同一内容の再取り込みは重複しない。注意記録は再取り込みでも注意と報告する。
同一IDのバイト列変更は別Rawとして残したうえで停止し、元のDB記録を更新しない。
別IDの観測は値が同じでも保存する。内容変更を市場の訂正と認定する機能はない。

`observed_at` は元の読取完了時刻。`available_at` は既存PIT規則に合わせ完了時刻+1秒。
`imported_at` は今回の取込時刻であり、提供元更新日時ではない。時刻はタイムゾーン必須、
読取開始≦完了≦取込時刻かつ観測時刻=完了を検査する。原本の時刻の真正性は保証しない。
約定日・公表日時・提供元更新日時はnull、接続状態はunknown、鮮度検証はfalseを維持する。
学習・バックテスト・売買判断に接続しない。

ParquetはDBの2テーブルから別世代へ出力し、件数を検査してから `current.json` を
原子的に更新する。出力失敗時も既存の公開世代を維持し、`--export-only` で再生成できる。
RawはGit対象外の `data/rss-store/raw`、DBは `rss.duckdb`、Parquetは `parquet` 配下。

既存プロジェクトのDuckDB接続・パラメーター束縛・トランザクションとPyArrow保存方式を利用した。
公式参照：[DuckDB Python DB API](https://duckdb.org/docs/stable/clients/python/dbapi)。

## 7. 発見した問題

## 9. 既知のリスク・制限

単一書込プロセスで利用する。共有DBを同時更新する構成には対応しない。
同一実行の全件一括確定ではなく1観測単位で確定し、途中失敗後は同じコマンドで再実行する。
Raw保存後のDB失敗では未参照Rawが残る。出力失敗では未公開のParquet世代が残る。
いずれも自動削除しない。過去の取込を行う入力の時刻は署名で検証されていない。
実行フォルダーは32文字の小文字16進ID、対象は3桁JSON最大60件・1ファイル1MiBまで。
summary.jsonの完了表示を要求せず、途中まで記録された観測も取り込めるため、
取込成功は実行全体の網羅性を保証しない。サイズ超過ファイルは読み込み前に拒否する。
Rawは元のJSONであり、市場データ提供元の通信応答そのものではない。
