# 複数データソースのカバレッジ監査

この監査は第1段階の取得済み価格・TOPIX・取引カレンダーを読み取り、指定期間の保存状況、
保存済み品質結果、Point-in-Time（PIT）利用可否を照合する。株価等を再取得せず、元のcatalogや
取得履歴を変更しない。全銘柄・全期間の網羅性や個別欠落の原因を確定するものではない。

## 対象と実行

対象は単一銘柄の日次株価、TOPIX日次、取引カレンダー。銘柄マスターと財務概要は初版の
照合対象外。期間は開始日・終了日を含む。価格の検索条件は正規化した銘柄コードと開始日・
終了日、TOPIXとカレンダーの検索条件は開始日・終了日で、それぞれ完全一致が必要。

```powershell
.\.venv\Scripts\python.exe -m trading_system.cli audit-coverage --code 86970 --from 2026-10-01 --to 2026-10-22
```

共通の `--data-root` を指定するときは、既定のデータ保存先を切り替えられる。必要に応じ
`--decision-at` にタイムゾーンを含むISO日時を指定する。省略時の判断時刻は監査実行時刻。
監査結果はJSONとして表示し、個別の監査receiptも保存する。監査全体の状態は
`clear`、`coverage_failed`、`blocked` のいずれか。終了コードは0=clear、3=coverage_failedまたは
blocked、2=入力・操作エラー。ソースごとの状態は `ready`、`empty`、`unavailable`、
`incomplete`、`indeterminate_at_cutoff`、`not_yet_available`、`quality_failed`。
該当検索条件の取得ジョブが判断時刻までに無い場合は `unavailable` とし、理由を
`no_exact_query_job_at_cutoff` として報告する。

## スナップショット選択とPIT

価格、TOPIX、カレンダーはそれぞれ、コードと期間を含む検索条件が完全一致する取得ジョブだけを
候補にする。各データセットについて判断時刻までに開始済みの候補から、最も新しく開始した
ジョブを1件選ぶ。同時刻はジョブIDで決定的に順序付ける。選択した最新ジョブが失敗・実行中・
未完了なら、古い正常ジョブへ切り戻さない。別ジョブの行を継ぎ合わせず、選択ジョブの観測と
版だけを判定に使う。

取得全体の確定時刻から1秒後、および各行の `available_at` が判断時刻以前の場合に限って
そのジョブ/行を利用可能とする。株価はterminal job update時刻、参照データは完了時刻を
取得確定時刻の根拠にする。保存された履歴から判断時点での最新ジョブ状態が確定できない場合は
「判定不能」とし、後から更新されたcurrent状態を過去へ投影しない。開始時刻や取得時刻だけで
利用可能だったとは判断しない。各データセットのDuckDBは個別の読み取りトランザクションで
確認するため、異なるcatalog間で単一の原子的スナップショットは保証されない。receiptには
選択したジョブ、版、ハッシュを記録し、その証拠の組合せを固定する。

## カレンダー照合と分類

日付区分1と2は東証営業日、0と3は東証非営業日として扱う。3（大阪取引所の祝日取引）は
東証個別株の営業日には含めない。比較は完全で品質正常な指定期間のカレンダー取得がある場合に
限る。カレンダー不足・品質異常・未完了時は、その状態を示し、株価/TOPIXの欠落日を確定分類しない。

有効な株価取得に営業日の行がなければ、原因未確定のカバレッジ不足として扱う。全OHLC・出来高・
売買代金がnullの行は、行が存在する「無約定」として数える。売買停止、上場状態、API未収録などの
理由はこの監査だけでは判別しない。無約定行を欠落行へ変換しない。

TOPIXは営業日に行が無ければカバレッジ不足、東証非営業日に行があれば異常候補として記録する。
このチェックは値の補正や行の削除をしない。株価/TOPIXの品質異常、ジョブ未取得、未完了、
正常な取得における日付欠落は別の状態として報告する。

## 監査記録

各実行はUUID付きの独立JSON receiptを `data/jquants/audits/coverage/` に保存する
（別の `--data-root` を指定した場合はその配下）。
receiptには監査ID、作成時刻、判断時刻、要求条件、選択した各ジョブの識別子・状態・時刻、
選択ポリシー、対象行と選択版の識別情報、Raw page・版・スナップショットの保存済みハッシュ、
日別比較、判定結果、制限を記録する。秘密情報や取得データ本文は含めない。既存receiptを上書きしない。receiptはその時点の監査記録であり、
過去の提供元状態を新たに再現する機能ではない。ハッシュはDBに記録された来歴・スナップショット
メタデータであり、Rawファイルを読み直して現在のファイル内容との一致を検証するものではない。
Parquetファイルの整合性検査も行わない。

## 制限

本監査は既存catalogを読み取り専用で開き、新規API要求を行わない。対象DBが存在しない場合に
新しいDBを作成せず、schema migrationも行わない。初回取得前の訂正履歴や当時の提供元状態は
復元できない。過去に存在した欠落や異常を全て確定する保証はない。Rawファイルの改ざん検知や
全アーカイブの完全性監査も行わない。

株価の営業日欠落を直ちに異常欠損とは断定しない。全nullの無約定と異常な欠損を区別しても、
無約定理由までは識別できない。現在の銘柄マスターを過去の株価へ適用しないため、上場期間・
上場廃止銘柄のカバレッジもこの版では判定しない。金額や価格の異常値を削除・補正・補完しない。
