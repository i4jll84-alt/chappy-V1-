# 短期・スイングの研究入力

## 日中に取得する銘柄数

固定組・日替わり組の同日比較では楽天で両組を観測する。11月13日までの固定30銘柄は11月2日の引け後に選んだ。東証3市場それぞれで過去20営業日の売買代金中央値を上位・下位に分け、6区分から各5銘柄を抽出した。既に選ばれた数が少ない業種を優先し、同順位は固定シードとコードのハッシュで決定した。30銘柄で26業種を含み、トヨタを別枠の比較銘柄とした。

11月16日からは、引け後に次の東証営業日用の候補30銘柄を作り、トヨタを加える。営業日は保存済みの公式カレンダーで決める。判断日の東証3市場・内国株券・コード末尾0から、直近5営業日すべての売買代金・出来高・四本値が有効なものを対象にする。期間中に権利処理があるものは除く。終値で100株に片道10円と0.05%を足して100万円以内を目安とする。売買代金中央値の上位100銘柄から、日中値幅率（高値と安値の差÷同日の終値）の5日中央値上位30銘柄を選ぶ。同値は売買代金、次に銘柄コード順。この条件は流動性と値動きを観測するための初期仮説で、翌日利益の有効性は未検証。

Windowsタスク JPX-DaytradeUniverse-AfterClose はログオン中の平日18時に当日分を保存する。実行を逃した場合は起動可能になった時点に直近の確定営業日を確認する。共通画面の「当日分を保存」でも16時30分以降に同じ処理を開始できる。翌営業日の候補・入力の版・日付別の研究ブックは data/rss-panel/daily/YYYY-MM-DD/ にまとまる。候補は最初の公開時に確定し、再実行でも入れ替えない。寄り付きまでに作れなかった日は研究取得画面に理由を表示する。既に開いている古い研究ブックは翌日の開始前に閉じ、チャート数の上限を空ける。カブコムは他の登録を保持するため、銘柄登録枠が不足すれば既存の上限案内に従う。
銘柄数を増やす必要が出た場合は、理由、追加候補と変更後の銘柄数、取得間隔への影響を利用者に示し、了承を得てから変更する。
追加銘柄の選定条件と適用開始日は事前に記録する。この件数は楽天・カブコムの日中取得に適用し、J-Quantsの日足は当日対象の全銘柄を保存する。

## 楽天の1分足と気配

### 同日の固定組・日替わり組の比較

2026年11月16日適用。毎営業日前の選定で、従来の固定30と日替わり30の所属・順位を対象日フォルダーの selection.json に保存する。共通銘柄と診断用トヨタを含めて取得対象を重複排除し、最大61銘柄を固定・日替わり交互に並べる。楽天は全対象の最良売買気配・数量・更新時刻を毎回同じ一覧から読み取る。50銘柄以下なら分足も全て同時取得し、51以上なら最大31本のチャート枠で2群を交代し、初期表示400本から1分足を回収する。配信表示と対象の取得式が一致してから保存する。切替中の古い出力は除き、分足が後から届いた場合は実際の受信以後に利用する。過去の手動ブックも合算されるため、初回は以前の31チャート研究ブックを閉じておく。日付別自動生成ブックは取得終了後にそのブックのみ保存せず閉じ、データはSQLiteで保持する。カブコムは登録上限が50銘柄なので、従来の日替わり30＋トヨタの補助観測を続ける。

Windowsタスク JPX-PairedIntraday-Capture が平日8時30分に、同一ユーザーのログオン中、東証営業日・当日分候補を確認して楽天の取得を開始する。開始を逃した場合は15時59分前まで追いつき実行する。MARKET SPEED IIの本人ログインとExcel RSSの「接続中・発注不可」が必要。手動STOPを自動解除しない。停止後は共通画面の研究取得ボタンで再開できる。夕方の候補作成は既存の18時タスクを使う。

引け後に楽天の取得が終了して日別共通DBを公開すると、開始日から当日までの模擬結果を data/research/paired-comparison/YYYY-MM-DD/比較結果.txt と result.json に保存する。各組は独立した100万円、100株単位、同一銘柄の当日買付は1回、売却代金は2営業日後に再利用。10時と13時30分に、受信済みの開始足の始値と直前5分の最新完了足の終値を比較し、上昇時のみ5分以内の適格な最良売り気配で模擬買付。売却は10時30分・14時以降の最初の適格な最良買い気配。板の鮮度は両側60秒以内、利用側の時刻は判断後、表示数量100株以上。片道10円と0.05%の費用を仮定。比較用トヨタを損益から除く。結果には銘柄別の判断、売買、欠測、未決済、日別資産・費用込み損益を記録する。観測不足や未決済があれば観測分だけを表示して優劣判定を保留する。再集計は python -m trading_system.research.paired_comparison --through YYYY-MM-DD。

[楽天RSSの銘柄数・関数上限](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_002/ohm_002_08.html) · [カブコムの登録上限](https://kabucom.github.io/kabusapi/reference/)

毎朝は共通画面で「楽天証券」「カブコム」「両方」から対象を選び、
「選択した証券会社の研究取得」を1回押す。「両方」で楽天とカブコムを同時に開始できる。
選択した証券アプリと楽天の研究用Excelは必要に応じて開く。片社の認証待ちの間ももう一社が取得する。
カブコムの「当日時刻」は、今回の取得で東京の当日付かつ読取完了以前の時刻を伴う正の約定価格、または正の価格・数量を伴う板の段を一度でも保存した銘柄数。「最終保存」は対象銘柄・市場が一致する板応答の読取完了時刻。照会しただけでは当日データに数えない。
専用ブックのRSSが「接続中・発注不可」であることを確認する。データが届かないときは「接続を確認（トヨタ1銘柄）」で確認できる。
稼働状態の「当日分足」は、直近の読み取りで日本時間の当日分足を確認できた銘柄数。価格が空欄で出来高ゼロの有効な足も含む。「最新」は全31銘柄で確認できた分足のうち最も新しい足の日時。寄り付き後も当日分足が0で最新が前営業日のままなら、MARKET SPEED IIへのログインとExcelのRSS接続状態を確認する。
「RSS配信中」は、研究用Excelのチャートが実際に「配信中」と表示した銘柄数。共通画面から起動し、RSS接続待ちの場合はMARKET SPEED IIのログインを確認する。ブックを先に開いた場合はExcelの「マーケットスピード II」タブで「未接続」のときだけ接続ボタンを押し、「接続中・発注不可」を確認する。前日分は寄り前にも表示される。寄り付き後は当日分の銘柄数と最新時刻が進むことを確認する。[楽天公式の起動手順](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_001/ohm_001_08.html)
チャートの配信表示を各取得原本に記録する。場中に未接続・配信未確認から全チャートが配信中に戻った場合は、次回に全体読取を行う。後から得た過去の分足には実際の受信時刻が付く。引け後の一括取得は全チャートの配信と当日分足が揃うまで最大4回確認する。休場日などで直近日の足だけが揃う場合は、その旨を表示して保存する。
旧固定ブックには31本のチャート関数を使用する。別ブックと合計で楽天のチャート関数上限50本以内に収める。
重複起動はロックで拒否する。指定したブックが見つからない、応答がない場合は自動で再確認し、状態欄に表示する。
手動停止は「すべての取得を停止」。終了後に同じ研究ボタンで再開する。場中の継続取得は日本時間06:00〜15:59未満に開始し、
16:00で新規読取を止める。既に始めた1回の読み取り（最大45秒）と保存は完了を待つ。PCをスリープさせない。
15:59以降に研究ボタンを押すと専用ブックを開き、31銘柄の直近分足・気配と日経平均（N225）・TOPIX（TOPX）を
一括取得して終了する。ブックを開いた直後の応答待ちでは最大4回確認する。「楽天の接続確認用Excelを開く」も夜間に使える。
指数はmarket_indexesに原表示の日付・更新時刻・値を保存する。出来高0かつ四本値がすべて空欄の分は価格NULLで記録する。

対象にカブコムを含めると、31銘柄の研究取得はローカルの本番APIの待受を確認し、接続可能になったらPC上にAPIパスワードの入力画面を開く。
待受が閉じている間は、kabuステーションの起動・ログイン・API設定を確認する。日中はSTOPまたは16時まで待機し、取得中に待受が閉じたときも通信失敗の原本を残して再開を待つ。引け後は起動から5分が接続・入力待ちの上限。
通常のカブコム単独取得とは
共通の書込みロックを取り、同時に認証しない。場中は31銘柄を順番におおむね毎秒1リクエスト以下で照会する。
引け後は原則1巡で終了し、一時的な通信失敗だけは同じ銘柄を最大1回再確認する。板照会によって銘柄は証券アプリに
自動登録される。既存登録を消さず、登録上限が返れば停止する。
保存先は `data/mufg-panel/research.sqlite`。samplesに取引時刻・受信時刻・価格・累計出来高・売買代金・VWAP・
応答品質、levelsに売買各最大10本の値段と数量を保存する。認証応答を保存しない。板のあることと直近の約定は別に扱う。
場中の板は巡回観測で、過去の板の再構築は行わない。

保存先は `data/rss-panel/research.sqlite`。framesに読取の開始・終了時刻と圧縮JSON原本、
quotesに銘柄別の価格・時刻・最良気配と数量の観測、barsに銘柄・足時刻ごとの初出と変更を保存する。
時点を指定する再生ではframes.known_atまでに得た版だけを使う。elapsed_minuteは時計上でその1分が経過した印で、
約定や後日訂正のないことの保証にはならない。株価・気配は異なる時刻に更新される。気配の鮮度判定は暫定60秒。
framesとquotesには読み取れなかった状態も残り、研究ボタンだけでは売買しない。

旧固定パネルの再現には、配列sampleにcodeを持つ30銘柄とcontrolに比較銘柄を指定した
固定リストを用意する。Node.jsの`@oai/artifact-tool`と`jszip`がある開発環境で
`node scripts/build_research_panel.mjs <固定リスト.json> data/rss-panel`を実行する。
日替わりのブックは翌営業日の候補と一緒に新規作成する。Excelに読み込ませる前に、対象日フォルダーのpanel.jsonの全銘柄と
ブックのシート順・銘柄配置・取得項目の見出し・取得用数式を全件照合する（旧固定ブックは347個）。余分な数式も拒否する。
「気配」A1は銘柄列の表示名。ここを通常の値に変更したり空欄にしたりしても起動できる。A1に数式を追加した場合は起動検査で拒否する。
Excelでの通常保存による計算結果・書式・内部情報の更新は許容する。
生成時のworkbook_sha256は来歴情報として残すが、保存後の起動可否には使わない。
読み取り時にも既存のPowerShell検査で銘柄・数式・見出しを確認する。
RssChartは銘柄ごとに見出し・日付・四本値・出来高を同じ値配列として取得する。日付列の最初の終了線（--------）までの末尾から指定行数を選ぶ。終了線が手前に移ったときも、線より下に残った古い表示を除く。最終行を調べた後でデータが取得範囲の次の行まで伸びていた場合は、その回を棄却する。取得用数式は値の読み取り前後で確認する。
日中は通常12行を読み、起動時と全体読み取りの成功から15回後に420行を読む。420行の読み取りに失敗したら、次に12行を1回読み、その次に420行を再試行する。Excel処理中や呼び出し拒否などの連続失敗では、最初の再試行だけ待機を15秒から3秒に短縮する。待機中もSTOPと16時終了を確認する。
Excelのプロパティ取得で呼び出し拒否・再試行要求を受けた場合は、そのプロパティの再取得前に200ミリ秒、2回目は400ミリ秒待つ。上限はフレーム全体で2回。再試行した箇所、プロパティ、銘柄（該当時）、HRESULTは、そのフレームの原本のproperty_retriesで確認できる。値や数式の配列が取得できない回、数式・銘柄・見出しが異なる回は価格保存に進まない。
各回の原本（研究DBのframes.raw_gzip）に要求行数を保存する。Excel読み取りエラーには処理箇所、該当する場合は設定銘柄とCOMのHRESULTを記録する。PowerShellの起動失敗・時間切れ・異常終了・応答形式不正も区別する。過去の原本に詳細をさかのぼって付与しない。
初回価格の遅れは、各銘柄・分足の価格が初めて記録されたフレームの受信完了時刻（known_at）から、その1分の終了時刻を引いて測る。Excel側での初回表示時刻とSQLiteのコミット完了時刻は別の時刻である。
状態欄には具体的な設定・ブック・保存先のエラー理由、または前回の一括取得結果を表示する。
[RssChartの公式仕様](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_002/ohm_002_04.html)

## 両社のデータを同じ分析で使う

研究取得が終了すると、受信した日本日付ごとに `data/research/shared-market/YYYY-MM-DD.sqlite` を更新する。
場中や再作成時は `python -m trading_system.research.shared_market --date YYYY-MM-DD` で両社の保存済み原本から再生成できる。
分析中にWindowsがファイル置換を拒否した場合は分析ソフトを閉じて再作成する。公開結果は取得元別のpublish.jsonに残る。
`quotes` の銘柄・最終取引時刻・受信完了時刻・株価・累計出来高・最良気配と数量の列は共通。
楽天の最良気配とカブコムの各最大10本は `book_levels` に売り／買いを揃えて保存する。
楽天の `minute_bars`・`market_indexes` も同じファイルに格納する。取れなかった値はNULL、取得元はsource列に残す。
同じ銘柄の2社の累計出来高を足さない。銘柄比較はsymbolで、J-Quants日足との照合はjquants_codeで行う。
known_atはUTCの受信完了時刻。任意時点での比較には `latest_asof(db, aware_datetime)` を使い、
その時点までに受信済みの各社の最終観測を取得する。古い気配・拒否された観測は品質・時刻を別途判定する。
この共通表には研究パネルで実際に観測した銘柄を記録し、以前のトヨタ単独確認と日足の全履歴は別の保存先にある。

## スイング研究

各営業日16:30以降に共通起動画面の「夜の作業（16:30以降）」で「当日分を保存」を押すと、
公式J-Quantsから当日の日足（全銘柄）・
同日の銘柄一覧・TOPIX・営業日区分・公表済み決算を取得する。Excelの起動や証券会社へのログインは不要。
進み具合と結果は「稼働状態」の「夜の当日分保存」で確認する。`scripts/save_swing_day.cmd` からも同じ処理を実行できる。
休場日はカレンダー確認で終わる。日付指定は `python -m trading_system.research.swing_daily --date YYYY-MM-DD`。
後日判明した訂正や、初回取得後の追加開示を収録する場合は `--refresh` を指定し、新たな観測として保存する。
日々の保存先は `data/jquants/daily-snapshots` と既存のreference・market_financial。
以下の過去期間の比較コマンドは一括履歴を入力とし、この日次取得だけで過去の履歴期間を更新するものではない。

`.venv/Scripts/python.exe -m trading_system.research.swing_windows --first 2026-09-01 --last 2026-10-30 --through 2026-10-30 --output data/offline-verification/swing-20261102`
で初回に生成済み。再計算には新しい出力名を指定する。各週の対象期間内最終営業日について、
その日のマスター（東証3市場・内国株券・末尾0）を使う。過去21営業日の終値から6特徴量を算出する。
結果は翌営業日の始値から5・10・20営業日後の始値まで。TOPIXも同じ日付の始値で比較する。
入退出時の始値なし、期間中の権利イベント、行不足、まだ到来しない結果を区別して記録する。
日付ごとの対象を事後の利益や存続の有無で削らない。原本とParquetはハッシュを照合する。
features.parquetとoutcomes.parquetは別々に使用し、後者を予測入力に使わない。
データの当時の入手時点をさかのぼって証明するものではなく、配当・費用を含む実行可能な利益率は評価していない。

## 11月13日の同日観測の照合

金曜の日替わり候補の先行観測は15:31 JSTに810巡で終了した。30銘柄すべてで、最後に保存した分足を集計した始値・高値・安値・終値・出来高がJ-Quants日足と一致した。10:00の判断に使えたのは13／30銘柄、13:30は30／30。午前の残り17銘柄も締切までに板が届いており、09:00足の四本値が空欄・出来高ゼロで、現行条件の開始価格を得られなかった。保存後に値を補って判定していない。

同日・各100万円で、研究用の固定デイトレルールを受信時刻順に再生。固定30は6往復・0勝6敗で費用後−2,505.45円、日替わり30は4往復・1勝3敗で−7,571.87円。いずれも未決済0件。板は注文側時刻・数量・鮮度を満たす記録を採り、同時受信では銘柄順とした。固定組の判断価格の組が確認できたのは午前15・午後13銘柄、日替わり組は午前13・午後30銘柄。この1日の比較には観測範囲の差がある。入力・照合・模擬約定明細はローカル `data/offline-verification/swing-short-controls-20261113/` に保存。
