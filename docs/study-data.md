# 短期・スイングの研究入力

## 日中に取得する銘柄数

楽天とカブコムの場中取得は同じ31銘柄（研究用30銘柄と比較用のトヨタ）で運用する。
まず複数営業日の分足と板を蓄積し、欠けた時間帯、板を一巡する間隔、業種や売買の活発さの偏りを確認する。
銘柄数を増やす必要が出た場合は、理由、追加候補と変更後の銘柄数、取得間隔への影響を利用者に示し、了承を得てから変更する。
追加銘柄の選定条件と適用開始日は事前に記録する。この件数は楽天・カブコムの日中取得に適用し、J-Quantsの日足は当日対象の全銘柄を保存する。

## 楽天の1分足と気配

毎朝は使用する証券アプリにログインし、共通画面で「楽天証券」「カブコム」「両方」から対象を選び、
「選択した証券会社の研究取得（31銘柄）」を1回押す。「両方」で楽天とカブコムを同時に開始できる。
楽天を含む場合は研究用Excelが自動で開く。
専用ブックのRSSが「接続中・発注不可」であることを確認する。データが届かないときは「接続を確認（トヨタ1銘柄）」で確認できる。
31銘柄研究用には31本のチャート関数を使用する。別ブックと合計で楽天のチャート関数上限50本以内に収める。
重複起動はロックで拒否する。指定したブックが見つからない、応答がない場合は自動で再確認し、状態欄に表示する。
手動停止は「すべての取得を停止」。終了後に同じ研究ボタンで再開する。場中の継続取得は日本時間06:00〜15:59未満に開始し、
16:00で新規読取を止める。既に始めた1回の読み取り（最大45秒）と保存は完了を待つ。PCをスリープさせない。
15:59以降に研究ボタンを押すと専用ブックを開き、31銘柄の直近分足・気配と日経平均（N225）・TOPIX（TOPX）を
一括取得して終了する。ブックを開いた直後の応答待ちでは最大4回確認する。「楽天の接続確認用Excelを開く」も夜間に使える。
指数はmarket_indexesに原表示の日付・更新時刻・値を保存する。出来高0かつ四本値がすべて空欄の分は価格NULLで記録する。

対象にカブコムを含めた場合は、PC上の専用画面でAPIパスワードを入力する。通常のカブコム単独取得とは
共通の書込みロックを取り、同時に認証しない。場中は31銘柄を順番におおむね毎秒1リクエスト以下で照会する。
引け後は原則1巡で終了し、一時的な通信失敗だけは同じ銘柄を最大1回再確認する。板照会によって銘柄は証券アプリに
自動登録される。既存登録を消さず、登録上限が返れば停止する。
保存先は `data/mufg-panel/research.sqlite`。samplesに取引時刻・受信時刻・価格・累計出来高・売買代金・VWAP・
応答品質、levelsに売買各最大10本の値段と数量を保存する。認証応答を保存しない。板のあることと直近の約定は別に扱う。
場中の板は巡回観測で、過去の板の再構築は行わない。

保存先は `data/rss-panel/research.sqlite`。framesに読取の開始・終了時刻と圧縮JSON原本、
quotesに銘柄別の価格・時刻・最良気配と数量の観測、barsに銘柄・足時刻ごとの初出と変更を保存する。
時点を指定する再生ではframes.known_atまでに得た版だけを使う。elapsed_minuteは時計上でその1分が経過した印で、
約定や後日訂正のないことの保証にはならない。株価・気配は異なる時刻に更新される。気配の鮮度判定は暫定60秒。
framesとquotesには読み取れなかった状態も残り、研究ボタンだけでは売買しない。

ブックは現在のPCに作成済み。別環境では、配列sampleにcodeを持つ30銘柄とcontrolに比較銘柄を指定した
固定リストを用意する。Node.jsの`@oai/artifact-tool`と`jszip`がある開発環境で
`node scripts/build_research_panel.mjs <固定リスト.json> data/rss-panel`を実行する。
稼働中のブックは差し替えない。Excelに読み込ませる前に、panel.jsonの31銘柄と
ブックのシート順・銘柄配置・見出し・取得用数式347個を照合する。余分な数式も拒否する。
Excelでの通常保存による計算結果・書式・内部情報の更新は許容する。
生成時のworkbook_sha256は来歴情報として残すが、保存後の起動可否には使わない。
読み取り時にも既存のPowerShell検査で銘柄・数式・見出しを確認する。
状態欄には具体的な設定・ブック・保存先のエラー理由、または前回の一括取得結果を表示する。
[RssChartの公式仕様](https://marketspeed.jp/ms2_rss/onlinehelp/ohm_002/ohm_002_04.html)

## 両社のデータを同じ分析で使う

31銘柄の研究取得が終了すると、受信した日本日付ごとに `data/research/shared-market/YYYY-MM-DD.sqlite` を更新する。
場中や再作成時は `python -m trading_system.research.shared_market --date YYYY-MM-DD` で両社の保存済み原本から再生成できる。
分析中にWindowsがファイル置換を拒否した場合は分析ソフトを閉じて再作成する。公開結果は取得元別のpublish.jsonに残る。
`quotes` の銘柄・最終取引時刻・受信完了時刻・株価・累計出来高・最良気配と数量の列は共通。
楽天の最良気配とカブコムの各最大10本は `book_levels` に売り／買いを揃えて保存する。
楽天の `minute_bars`・`market_indexes` も同じファイルに格納する。取れなかった値はNULL、取得元はsource列に残す。
同じ銘柄の2社の累計出来高を足さない。銘柄比較はsymbolで、J-Quants日足との照合はjquants_codeで行う。
known_atはUTCの受信完了時刻。任意時点での比較には `latest_asof(db, aware_datetime)` を使い、
その時点までに受信済みの各社の最終観測を取得する。古い気配・拒否された観測は品質・時刻を別途判定する。
この共通表の対象は31銘柄の新しい研究取得で、以前のトヨタ単独確認と日足の全履歴は別の保存先にある。

## スイング研究

各営業日16:30以降に共通起動画面の「夜の作業（16:30以降）」で「当日分を保存」を押すと、
公式J-Quantsから当日の日足（全銘柄）・
同日の銘柄一覧・TOPIX・営業日区分・公表済み決算を取得する。Excelの起動や証券会社へのログインは不要。
進み具合と結果は「稼働状態」の「夜の当日分保存」で確認する。`scripts/save_swing_day.cmd` からも同じ処理を実行できる。
休場日はカレンダー確認で終わる。日付指定は `python -m trading_system.research.swing_daily --date YYYY-MM-DD`。
後日判明した訂正や、初回取得後の追加開示を収録する場合は `--refresh` を指定し、新たな観測として保存する。
日々の保存先は `data/jquants/daily-snapshots` と既存のreference・market_financial。
以下の過去期間の比較コマンドは一括履歴を入力とし、この日次取得だけで過去の履歴期間を更新するものではない。

`.venv/Scripts/python.exe -m trading_system.research.swing_windows --first 2026-09-01 --last 2026-10-30 --through 2026-10-30 --output data/offline-verification/swing-20261102`
で初回に生成済み。再計算には新しい出力名を指定する。各週の対象期間内最終営業日について、
その日のマスター（東証3市場・内国株券・末尾0）を使う。過去21営業日の終値から6特徴量を算出する。
結果は翌営業日の始値から5・10・20営業日後の始値まで。TOPIXも同じ日付の始値で比較する。
入退出時の始値なし、期間中の権利イベント、行不足、まだ到来しない結果を区別して記録する。
日付ごとの対象を事後の利益や存続の有無で削らない。原本とParquetはハッシュを照合する。
features.parquetとoutcomes.parquetは別々に使用し、後者を予測入力に使わない。
データの当時の入手時点をさかのぼって証明するものではなく、配当・費用を含む実行可能な利益率は評価していない。
