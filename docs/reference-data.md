# 銘柄マスター・取引カレンダーの設計

第1段階の追加データ。価格用の既存DBとは別に、`data/jquants/reference/master/` と
`data/jquants/reference/calendar/` に保存する。データの利用権と廃棄対象は同じJ-Quants配下で管理する。

## 公式仕様の確認

- [銘柄マスター](https://jpx-jquants.com/ja/spec/eq-master)：日付を指定して当時の一覧を取得する。
  休日・提供範囲外等では要求日と適用日が異なる場合があるため、返されたDateを保持して差を警告する。
- [カレンダー](https://jpx-jquants.com/ja/spec/mkt-cal)：日付範囲の両端を含む全暦日を取得する。
  公表/更新時刻や訂正識別子は提供されないため、取得時刻と混同しない。
- [休日区分](https://jpx-jquants.com/ja/spec/mkt-cal/holiday-division)：1と2を東証営業日として扱い、
  0と3は東証非営業日。3は大阪取引所の祝日取引を表す。
- [商品区分](https://jpx-jquants.com/ja/spec/eq-master/product-category)：ProdCatを保持する。
  ETFやREITをマスター取得段階で削除しない。011だけで普通株式と優先株式を判別しない。

## データと品質

Raw本文とメタデータ、取得ジョブ、HTTP試行、ページ、全観測行、品質問題、版を保存する。
正規化列は適用日、コード、会社名、市場、業種、商品区分、休日区分、東証営業日フラグ等。
未知の項目もRawとpayload_jsonに残す。同一内容/同一品質は版を増やさず、訂正や品質変更を履歴化する。
同一ジョブ内で同じキーに異なる内容が現れたら、そのジョブ中は異常扱いを維持する。

必須項目の型、不正日付・コード、休日/商品区分、範囲外の日付を検査する。
カレンダーでは要求範囲の暦日欠落を検査する。銘柄マスターでは実適用日が複数日に混在した一覧を
異常扱いにする。単一の異なる適用日については、日付の対応理由を自動で断定せず警告として残す。

## 時点と一覧の扱い

`ReferenceStore.as_of(decision_at, params)` は、指定した検索条件の取得済み一覧を返す。
paramsを省略した場合は最新の検索条件の一覧を選ぶため、用途が決まっている場合は必ず指定する。
最新版を全銘柄・全日付から単純に寄せ集める方式ではない。再取得で消えた銘柄を過去の一覧から混ぜない。
途中までしか取得できていないジョブは選択しない。最新の確定ジョブが品質異常なら一覧全体を返さず、
以前の正常な一覧への暗黙の切戻しもしない。

行のavailable_atは観測+1秒。一覧の利用はさらに、全ページ保存と品質検査を終えた
completed_at+1秒以降に限定する。completed_atはデータ取得・検査の完了時刻であり、
Parquetファイル生成の完了時刻ではない。公表日時は不明としてnullのまま保存する。
これらは取得以前の歴史的な利用可能時刻を復元する機能ではない。

`reference_current`は各キー/適用日の最新観測版を確認する監査用ビューであり、
特定日の全銘柄一覧や取引対象ユニバースとして直接使わない。
as_ofを使わずParquetの全世代をまとめて読み込むと、履歴や途中の観測も混ざる。

## 復旧と制限

Raw保存後、ページの正規化・品質結果・次ページ位置を同じDBトランザクションで確定する。
ParquetはDBから再生成できる世代方式で、全出力を読み戻した後にlatest.jsonを置換する。
ファイルとDBを跨ぐ原子的な確定はできないため、DBを正として再開・再生成する。
取得済み条件の再実行でもParquetをDBから生成し直し、古い/破損した世代を正常と誤認しない。
完了には保存済み最終ページ（次cursorなし、ページ番号とcheckpoint一致）を必要とし、
完了時刻は全ページ観測時刻以上とする。未完了や既存終端ジョブを再finishできず、
fetched・export_failed・終端ジョブへ追加ページを保存しない。終端状態へのfailも変更を行わない。
DB確定後にreceipt書込みが失敗しても完了状態・完了日時を保持する。キャッシュ再実行は
Parquetを再出力するが、欠落したreceiptファイル自体は再作成しない。DBの取得履歴は保持される。

ページング中に提供元が更新した場合の完全な一貫性は保証されない。
過去全日付のマスター収集、上場日/廃止日の完全復元は未実装。最新マスターを過去の株価へ流用して
生存者バイアスを発生させない。参照データ追加後に実装した株価・TOPIXと営業日の照合は
[カバレッジ監査設計](coverage-audit.md)、財務/TOPIXの取得は
[市場・財務データ設計](market-financial-data.md)を参照する。
HTTP応答全体のJSON構文やdata配列構造が壊れている場合は既存HTTPクライアントが拒否するため、
その本文のRaw隔離保存は未実装。行内の型異常はRawと品質結果に保持する。
