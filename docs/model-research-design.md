# 第3段階: 予測モデル研究の初期基盤

2026-10-23の次段階への指示により着手する。合成シナリオを使って学習・評価の手順を
検証し、第1段階・第2段階から続く実市場データの不足を解消済みとは扱わない。
実注文、証券会社接続、実市場でのモデル採用は対象外。

## モデルと公式仕様

指示書の第一候補LightGBMと単純なベースラインを比較する。既存環境にはLightGBMが
未導入だったため、プロジェクトの仮想環境へ4.7.0を導入した。依存するSciPy 1.18.1、
Narwhals 2.27.1もlockファイルに記録する。CatBoost、XGBoost、金融LLMは本工程で追加しない。

- [LightGBM 4.7.0 配布情報](https://pypi.org/project/lightgbm/4.7.0/): Windows wheelを使用。
- [学習API](https://lightgbm.readthedocs.io/en/v4.7.0/pythonapi/lightgbm.train.html): Datasetと明示パラメータで学習。
- [パラメータ](https://lightgbm.readthedocs.io/en/v4.7.0/Parameters.html): CPU、乱数種、スレッド数、deterministic、force_col_wise等を固定。
- [Booster](https://lightgbm.readthedocs.io/en/v4.7.0/pythonapi/lightgbm.Booster.html): ネイティブのモデル文字列を保存・再読込みする。

モデル文字列と特徴量順序、学習設定、学習データの出所をJSONに保存する。pickleを
用いない。ネイティブ形式も任意の外部入力を安全に実行できる保証ではなく、この基盤が
生成したモデルを再読込みするために使う。再現性は固定した実行環境で検証し、異なる
ライブラリ版・CPU・コンパイラでのビット一致を保証しない。
モデルの`trained_at`と予測の利用可能時刻は合成シミュレーション上の論理時刻であり、
PCで学習を実行した壁時計の時刻ではない。推論の所要時間はモデル化していない。

## 時点管理と予測対象

初期特徴量は価格から作る過去リターン、移動平均との比、ボラティリティに限定する。
各予測時点で必要な過去の価格が実際に利用可能な場合だけサンプルを作る。将来の値や
未提供の値で埋めず、除外した行と理由を残す。財務・信用残・投資家情報・出来高を
作り物の値で追加しない。

予測期間は5・10・20・60営業日。終値で判断した後の翌寄付から、保有期間経過後の
寄付までのリターンを正解とする。現在の終値で約定したことにしない。
正解の判明時刻も保存し、訓練・検証の境界にかかるラベルを学習へ混ぜない。
検証ラベルは最終学習の締切までに判明したもの、最終評価ラベルは入力シナリオの最後の
判断時刻までに判明したものに限定する。対象日が過去でも提供が遅れた値は使わない。
最終評価で将来の寄付が欠ける場合や正解の提供が遅れる場合、都合のよい銘柄・日付だけを
残さず研究実行全体を拒否する。将来の約定可否を予測時点の銘柄選択に使わないためである。
初期研究入力では企業行動を含むシナリオを拒否し、調整済み価格と現金権利を二重計上
するような不正な学習目標を作らない。第2段階の企業行動テストは引き続き利用できる。

## 学習と最終評価

訓練、モデル選択のための検証、最後の未使用期間を時系列順に分ける。特徴量の尺度や
モデル係数は学習区間だけで求める。候補集合と評価方法を固定し、不採用を含めて結果を
残す。最終期間を見て候補・しきい値・予測期間を調整しない。
候補ごとの学習・検証の成否を選択前に保存し、選択を固定してから最終評価を消費する。
同じ実験の再実行は保存結果を返し、最終評価を繰り返さない。ローカルの単一書込みを前提とし、
手動編集や別の保存先・別実験を作ることによる同じ期間の再利用までは防止しない。

モデルの予測誤差と売買シミュレーションの損益を別々に記録する。比較する戦略には
同じ評価期間、初期資金、取引単位、費用、流動性・信用在庫制約を使う。最後まで保有期間を
観測できない新規注文は出さず、最終日に架空の強制決済をしない。
モメンタム比較も予測と同じ銘柄・判断時刻の組だけで行い、評価開始は両者とも保有ゼロとする。
売買予測の符号を使う初期方式であり、独立した下落予測器と買い予測反転の比較は未実装。
モデル選択は事前に固定した検証誤差と改善基準による。統計的有意性の検定や、取引損益の
改善が証明されたという意味ではない。実TOPIX超過・リスク調整後リターンの予測も未対応。

合成データで良い指標が得られても実市場での改善とは判定しない。実モデルの採用には、
実市場の時点別入力、複数年度と急変期、取引コスト、過剰最適化を追加検証する必要がある。
本工程は各候補の学習・保存・再予測と、評価経路の再現性を確かめる。
