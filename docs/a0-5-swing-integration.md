# 個別株自動売買ツールV1への A0_5 順張りスイング取込指示書

2026年11月16日 ｜ 取込候補 ｜ 現物買い・ペーパー検証用

## 1. V1で実装するもの

V1の手法一覧に「A0_5 順張りブレイクアウト」を初期状態オフの選択肢として追加する。引け後に候補と理由を確定し、翌立会日の寄付で仮想約定を記録する。前向きペーパーは元本100万円と300万円の独立口座で並行記録する。固定履歴再現の500万円は再現基準として維持し、前向き口座に混ぜない。切替前の500万円台帳は保存し、以降の記録先に使わない。既存の機械・サブエージェントの4口座（各200万円）は比較対象として従来のルールと資金で継続する。A0_5の採否・順位・保有枠を他手法の候補と混ぜない。今回の取込範囲はペーパーまでとし、証券会社への発注・訂正・取消経路は接続しない。[V1の既存4口座と日次の流れ](swing-forward.md)

この文書は実装依頼時の仕様とする。手法の登録、過去検証の実行、日次運転の開始はそれぞれ実施状態を記録する。実装は次の順で進める。まず固定入力から元の売買を再現し、その後に決算回避・T+2管理を加えたペーパー運用を接続する。2つの結果にはそれぞれ「固定履歴再現」「運用ガード付きペーパー」と明記する。

## 2. 固定する売買仕様

移植元の版は `68dbce1d520d03d19107c5571da59d931bf1da33`。固定設定 `A0_5`、特徴量 `features`、順位 `ranked_candidates`、注文作成 `orders` を参照する。空売り・押し目買い・ATR・個別株の長期移動平均・TOPIXの追加SMA75は採用しない。[設定](https://github.com/i4jll84-alt/kobetutoredosutairukouann/blob/68dbce1d520d03d19107c5571da59d931bf1da33/swing_system/config.py)・[特徴量](https://github.com/i4jll84-alt/kobetutoredosutairukouann/blob/68dbce1d520d03d19107c5571da59d931bf1da33/swing_system/data_processor.py)・[順位と注文](https://github.com/i4jll84-alt/kobetutoredosutairukouann/blob/68dbce1d520d03d19107c5571da59d931bf1da33/swing_system/strategy.py)

| 判定 | 条件。日付 t は判定日の引けを表す |
|---|---|
| 対象市場 | t 時点の国内普通株（`ProdCat == "011"`、原本コード末尾が `0`）。2022年4月4日より前は `0101, 0102, 0106`、同日以降は `0111, 0112`。上場廃止銘柄も当時のマスターで判定する。 |
| 流動性 | t を含む連続20立会日の平均売買代金が5億円以上。 |
| 地合い | TOPIX終値が t を含む20日単純移動平均を上回り、有効な投資部門別の海外投資家差引売買代金 `FrgnBal > 0`。 |
| 業種の強さと資金流入 | 対象市場の銘柄を **17業種（S17）** に分け、欠損・`99` を除く。同業種の個別株20日騰落率の中央値がTOPIXの20日騰落率を上回り、当日の業種売買代金シェアが当日を除く過去20日の平均シェアを上回る。シェアの分母は対象業種の当日売買代金合計。 |
| 業績・信用 | 直近の公表済み決算で売上高と営業利益がともに前年同期を上回り、当期営業利益は正。有効な信用買残 `LongVol` ÷ 前日までの20日平均出来高が5以下。 |
| ブレイクアウト | t の終値が、t を除く直前20立会日の**高値の最大値**を厳密に上回る。t の出来高は前日までの20日平均の1.50倍以上。比較する高値・終値・出来高の株式分割等の調整は移植元に合わせる。 |
| 優先順位と枠 | 20日平均売買代金の降順、同値ならコード昇順。最大5銘柄、1日新規2銘柄まで。同一**33業種（S33）** は保有と当日採用を合わせて2銘柄まで。既保有銘柄の買い増しはしない。 |
| 株数と執行 | t 引けの評価総資産の20%と残余現金の小さい方を上限とする。想定買単価は t 終値 × 1.001 × 1.0005。上限内の100株単位に切り捨て、翌立会日の始値で仮想執行する。買いは始値に10bp加算、売りは10bp減算し、各約定代金に手数料5bpを1回適用する。 |
| 手仕舞い | 終値が当日を含む10日単純移動平均を下回るか、買付日を1日目として15立会日に達した日に全株の売りを予定し、翌立会日寄付で決済する。 |

履歴再現では、引けの買付枠計算に翌朝の予定売却を織り込まない。翌朝のギャップで現金不足になった買い、権利落ち当日の新規買いは失効。始値がなければ架空の約定を作らず、未執行の売りは次回へ繰り越す。保有中の権利処理、期末建玉評価、複数の売却理由が重なった場合も移植元の約定記録と照合する。[参照用約定エンジン](https://github.com/i4jll84-alt/kobetutoredosutairukouann/blob/68dbce1d520d03d19107c5571da59d931bf1da33/swing_system/backtester.py)

## 3. 入力の接続と時点管理

| 必要な入力 | V1で確認する項目 |
|---|---|
| 日足・銘柄マスター・東証カレンダー | V1の日足受領票の検証を利用する。全市場の日付・コード・始値・高値・終値・出来高・売買代金・調整係数・権利種別、当時の市場・商品区分・S17・S33と立会日を照合する。日中監視銘柄のリストで母集団を絞らない。原本コード・市場・業種は文字列で保持し、V1表示コードは日付付きマスターで対応付ける。 |
| TOPIX・投資部門別 | TOPIX日足終値と投資部門別の `Section, EnDate, PubDate, FrgnBal`。2022年4月14日公表分からプライムを使う。旧系列は `TSE1st` かつ期間末が再編前、新系列は `TSEPrime` かつ期間末が再編後とする。 |
| 決算・信用残 | 決算開示日・時刻、書類種別、期間、売上高、営業利益。前年の会計期間・書類種別を合わせる。信用は銘柄別の `Date, Code, PubDate, LongVol` を使用する。日証金の貸借残高や直近の銘柄属性で代用しない。 |

決算、投資部門別、実公表日が基準日より後の信用残は、公表日の**翌立会日**から有効。信用残で公表日が欠損する場合は、基準日後の第3立会日引けにみなし公表、第4立会日から使用し、推定フラグを残す。公表日の値が存在し基準日以前のものは無効とする。休場日、週次から日次への切替、訂正前後の版、分割後の信用残、`FinKnown / MarginKnown / FlowKnown` の鮮度は移植元の判定を引き継ぐ。

V1では各入力の基準日・公表日・みなし公表日・実取得完了時刻・版／ハッシュを区別する。前向きペーパーは判定締切までにV1が受領済みの版のみを使う。後日受領した訂正や翌朝の始値を前日の判断へ戻さない。過去の固定Parquetによる再現は別に記録する。足りないデータセット・項目・対象日は一覧にしてその判定を停止する。[V1の日足受領票検査](../src/trading_system/research/swing_daily.py)・[V1開発規約](../AGENTS.md)

## 4. V1への組み込みと日々の扱い

1. **手法選択と保存先**　`src/trading_system/research/a0_5.py` を新設候補とし、入力変換、固定ルール呼び出し、仮想口座入出力を接続する。ルールは参照元の固定版をモジュール単位で再利用するか、同版から移植し出典を記録する。V1の起動画面に手法名と有効状態を表示し、有効化は明示操作にする。学習や信頼スコアは不要。既存のデータ収集結果を読み、A0_5の判定時点は前日引けに固定する。
2. **引け後の判定**　必要データを検証して入力を固定し、保有の売り予定を上段、新規の買い予定を下段に表示する。候補、順位、採否理由、現金・株数・枠、判定日・予定日、入力版を記録する。候補ゼロとデータ異常による生成停止を区別し、古い予定表を再掲しない。
3. **データ鮮度**　直近の確定立会日と判定日の不一致、翌立会日等のカレンダー不足、データ完備銘柄数2,500未満は予定CSV生成停止。2,500は対象市場内で信用・決算・フローと必要特徴量が揃った銘柄数であり、5億円条件の適用**前**に数える。有効信用残銘柄数が「当日対象市場銘柄数と直前最大5立会日の有効件数中央値の大きい方」の80%未満でも停止する。過去件数がない場合は当日対象市場数を使う。
4. **運用ガードと受渡**　売り理由の優先順は `EARNINGS_AVOID → SMA10_BREAK → MAX_HOLD_15D`。翌立会日の決算は翌朝寄付で手仕舞う。新規は買付予定日を1日目とする3立会日以内の決算を見送り、繰上げ補充はしない。予定の原本・確認日を記録し、取得不能時は当日確認済みの手入力を許し、未確認の買いは保留する。分割・併合は新規の1日見送り推奨と保有株の株数・10日線の確認を表示する。売却で空く枠を使う案に「売り成立条件付き」を付ける。T+2未受渡額は受渡まで買付余力から除く。[運用ガードと枠計算の原本](https://github.com/i4jll84-alt/kobetutoredosutairukouann/blob/68dbce1d520d03d19107c5571da59d931bf1da33/swing_system/live_screen.py)
5. **翌朝・引け後の記帳**　始値が検証できた銘柄だけを仮想約定し、条件付き買いは必要な売りの成立・現金・枠を再確認する。V1のペーパー停止状態を尊重する。独立したローカル保存先（案 `data/a0-5-paper/`）に残高、受渡日付き拘束額、保有、日別予定、約定、取引台帳を置く。手法・仮想口座・予定日・売買・銘柄をキーに二重計上を防ぎ、訂正は別版にする。実測滑りは実約定を記録した場合のみ寄付比で計算し、モデル滑りとは別欄にする。監査画面には売買別・片道平均の滑り（警戒ライン+25bp）、想定コストとの差額、ルール遵守率、決済ベースのPF・勝率・ペイオフ・実現損益のMDDを表示する。OneDriveは使用せず、GitHubにはコード・仕様・テストのみを残す。取得原本、口座、台帳、認証情報はローカル限りとする。[V1の既存ペーパー処理](../src/trading_system/research/swing_forward.py)
