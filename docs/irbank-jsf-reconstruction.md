# IRBANK履歴取得とプランA原条件・近似条件の比較

## 範囲

ローカルの個別株自動売買ツールV1で取得・研究を行う。実口座・ペーパー口座・元の研究原本は変更しない。
ユーザーは原条件版と「市場合算・後日更新値・制限措置空欄」の近似版を別の研究として比較することを承認した。
近似版への採用変更や有料期間への延長は承認されていない。
原条件の完全復元は未完了。取得完了・数値一致・過去時点で利用可能だったことは別々に扱う。
全10年・前半5年成績を欠測のゼロ補完で作成しない。

## API仕様と保存

- ベースURL: https://api.irbank.net/v1/、認証: Authorization: Bearer <API key>。
- キーは環境変数、ローカル.env/.env.local、Windowsユーザー環境変数から読む。Git・ログへ保存しない。
- jsf-margin-daily は period=1y で最大252営業日。toで過去へ遡る。
- days: date, loan_balance, stock_loan_balance, net_balance, loan_new, loan_repay,
  stock_loan_new, stock_loan_repay, loan_balance_change, stock_loan_balance_change, lending_ratio。
- 逆日歩: reverse / other_exchange_reverse の date, fee_per_day, fee_days, fee_total。
- 制限措置は未収録。exchange=XTKSによる逆日歩の市場分けを、残高の東証限定とは解釈しない。
- 日付は申込日。当時の資料版・公表時刻は未証明。取得時刻を公表時刻に代入しない。

## 日次自動取得と上限

ユーザーの2026-11-22の指示により、2026-11-23〜2026-12-01の毎日21:00 JSTに取得する。土日祝も含む。
Codexのこのチャットに紐づく予約IDはirbank-5。既存のJPX無料資料取得・楽天確認とは別の取得予約である。
開始日は11月23日、最終実行日は12月1日。通信自体は12月1日22:30 JST以降を拒否する。
有料期間へ自動延長せず、IRBANK契約側の自動課金設定も変更しない。

日次上限は1,000データ要求、試用期間合計は10,000データ要求。
GET /usageは公式仕様で日次枠を消費しないため、quota_accounting=data_onlyでは日次・期間合計に含めない。
通信総数は従来どおりすべてSQLiteに保存し、無料の使用量確認と区別する。
初回試験分もinitial_data_requestsとして期間合計へ加える。リトライ・応答不明はデータ試行数へ加える。
他のAPI/MCP利用が枠を消費した場合は、API側の残数を優先して停止する。
期間合計に到達する日は1,000回に満たなくても終了する。

実行: .venv/Scripts/python.exe -B -X utf8 -m trading_system.research.irbank_daily
確認のみ: 同じコマンドに --inspect を付ける。事前確認では通信・認証情報の読取・台帳の新規作成をしない。
開始前、日次枠消費済み、期間合計到達、期限後は通信しない。
元の1回950通信の上限を保持し、その上限で止まった場合は日次処理内で再開する。
同日最大6バッチを超えてループせず、二重実行はOSロックで止める。
日付をまたいだ実行は停止し、過去日へ使用数を付け替えない。

data/irbank_jsf/acquisition-policy.jsonを必須とし、期限・日付範囲・日次・期間上限を検証する。
各データ要求の直前に無料の使用量確認を行い、通信間隔は1.1秒以上とする。
429/5xxは指数バックオフ、連続429で中断する。エラーや原文不一致を日次枠到達として扱わない。
404は同じリクエストの空キャッシュとして保存するが、残高ゼロとはしない。
正常ページは対象日を実際に含む場合に再利用する。曖昧な404を別期間へ流用しない。
原文とreceiptのSHAを検証し、不整合・片側だけの保存は勝手に上書きせず停止する。
台帳が欠けた場合も新規作成して枠を復活させず、確認が必要な状態として止める。

日別の実行結果はdata/irbank_jsf/daily/YYYY-MM-DD/、取得checkpointはstate/、
直近の進捗はprogress.json、提供元の残数はlast-usage.jsonへ保存する。
期限・期間合計・対象取得完了に達したら、予約から自身を削除して終了する。
日次取得は原文保存を進めるもので、原条件への統合ゲートや研究の前提を変更しない。

従前のall_http設定と日付限定daily_extensionsも互換性を維持する。
新しい予約期間ではdaily_scheduleの上限を使い、無料の使用量確認によって期間枠が早く尽きないようにした。

## PC・Codex起動時の補完

ユーザーの追加指示により、WindowsタスクIRBANK-Trial-CodexStartupを登録した。
ログオン時および1分間隔で、同一WindowsセッションのCodex本体の起動を確認する。
renderer・補助プロセス・CLIは対象にしない。プロセスのコマンドラインは保存しない。
実行先はこのプロジェクトの.venv/Scripts/pythonw.exeで、コンソールを表示しない。
Windows標準PowerShellは読み取り専用のプロセス確認にだけ使い、実行ポリシーやPCの電源設定は変更しない。

直前の21時の取得が未完了なら、次にPC/Codexが利用可能になった確認時に同じ日次処理を呼ぶ。
最初の予約時刻より前には開始しない。前夜の枠を消費済みなら翌朝に再取得しない。
翌日に補完する場合はその日の残枠だけを使い、前日分を繰り越して1,000回を超えない。
既取得原文とcheckpointを利用し、プランA前半5年の優先を維持する。

21時の予約と起動補完はdaily-dispatchロックを共有する。
二重起動はalready_runningとして扱い、異常終了としない。
失敗は同一アプリ起動・同一予約時刻に対して毎分再試行せず、次のアプリ起動または次の21時に再開できる。
中断された処理は完了とせず、ロック解放後にcheckpointから復旧する。
予約irbank-5がPAUSEDまたは削除済みの場合、起動補完は通信しない。

通常ユーザー権限・多重起動IgnoreNew・StartWhenAvailable有効。
タイマーとログオンの両トリガーは2026-12-01 22:30 JSTで終了し、期限切れタスクは1日後に削除される。
プログラム側も日次1,000・期間合計10,000・無料期限を毎回確認する。
補完記録はdata/irbank_jsf/startup/status.jsonと時刻別JSONへ保存する。

確認: scripts/check_irbank_startup.ps1 -InspectOnly
登録内容の確認: scripts/register_irbank_startup.ps1 -Preview
関連99件の試験と全体Ruff検査が成功。
実機ではタスクの実登録・期限・実行結果0を読み戻し、開始前に追加API通信しないことを確認した。
将来の電源オフ・再起動そのものは実行しておらず、翌朝・翌日・失敗後の再開は仮想時刻と隔離台帳で検証した。
検証記録・タスクXMLはローカルdata/offline-verification/irbank-startup-20261122/に保存する。

## 取得順序

同日の上場マスター・国内普通株・東証旧市場を含む対象を固定し、上場廃止銘柄も除外しない。
対象期間に一度でも売買代金1億円以上の母集団と、開始境界の判定に必要な銘柄を別々に記録する。
照合100銘柄はトヨタ＋固定SHA順位99銘柄で、成績を見る前に決める。

前半5年を優先する --phase first5 は、既存A0の固定テクニカル条件に該当した順に対象を並べる。
同じ銘柄は1度にまとめ、2016-11-17〜2021-11-19の原文を遡って保存する。
これは取得順序の優先付けであり、母集団・取引ルール・後半期間の削除ではない。
バックテストの損益や将来成績による選別は行わない。
--phase history は元の母集団全体を2023-10-31まで補完する。
週次信用APIは全プラン最大52週で、課金期間の延長だけで2016年まで遡れるものではない。

実行例: .venv/Scripts/python.exe -B scripts/fetch_irbank_jsf.py --phase first5 --max-requests 950
同じコマンドで再開できる。並列起動はdispatchロックで拒否する。
取得銘柄数・必要回数の見積もり・取得範囲はローカルのuniverse.jsonとprogress.jsonを確認する。

## 整合性と原条件の扱い

元のプランA研究が固定した公式原本と、同じ申込日の融資・貸株・差引残高を照合する。
元の研究の11月更新資料も優先して使用し、ペーパー運用の別保存版と混同しない。
市場集計の違いと後日更新を別々に診断し、原本を後日版で上書きしない。
差の理由が説明できても同じ値とは扱わず、原条件への統合ゲートはneeds_reviewを維持する。
audit-report.json / audit-diagnostics.jsonに原本SHA、項目別件数、日付ずれ診断を保存する。

## 原条件・近似条件の比較

共通期間は2023-11-01引け〜2026-11-19引け、初期資金各300万円。
A0の固定100株・費用込20万円の候補上限・上位5・2ATR出口・期限・T+2受渡を共通とする。
費用は片道10円＋0.05%。追加片道滑り0.10%も同じ2条件で確認する。

これは公式データによるIRBANK相当条件の比較であり、全銘柄IRBANK実データの再生ではない。
市場・資料版・制限除去は複合変更で、差を各要因の個別効果とは解釈しない。
未観測銘柄、期限始値欠測の仮決済、終値欠測時の仮評価は別記する。
新規口座で2回再生し、全資産・約定・買付・例外・期末保有・受渡を照合する。
全10年・前半5年の成績に読み替えない。

## 11月22日追加: 前半5年の2条件を取得後に評価

ユーザー承認の比較だけを trading_system.research.irbank_first5 に分離した。

追加API通信なしで準備状態を確認する。Windows起動補完も同じ日次経路を使う。
既存21時予約では終了・削除を判定する前にもこのローカル検査を行う。

対象は2016-11-20〜2021-11-20（休日境界を直前立会日引けに合わせる）。
各300万円、固定100株、元の候補順位・上位5・出口・T+2を維持する。
片道10円＋0.05%と、追加片道滑り0.10%をそれぞれ計算する。
固定した研究エンジン58ファイルのSHAをローカル設定へ保存し、将来のルール変更時は停止する。
候補の原入力SHA・営業日・市場原本も照合する。

- 原条件: 凍結済み東証残高・実際の制限措置・元の資料版が必要。
  これが不足している期間は待機し、費用控除後損益をnullとする。
  IRBANKの取得完了だけでは、これらの原資料が揃ったことにならない。
- 近似: 固定対象全銘柄の前半取得windowを確認してから、
  原文SHA・ページの連続性を確認する。IRBANKの市場合算・後日値を使用し、
  制限措置を空欄通過とする。元の照合needs_reviewは解除しない。
  404や日付欠測はゼロ残高にせず、選外件数・日付・銘柄を全判定に記録する。
  この場合credit_coverage=partialとし、完全な前半復元とは扱わない。

一方が不足・不正でも、もう一方の成立する研究は進める。
新規口座で2回再生し、資産・約定・買付・例外・期末保有・受渡を比較する。
両条件が計算できた場合だけ費用控除後損益等の差を計算する。
